Partitioning 핵심 개념
파티셔닝은 큰 테이블과 인덱스를 작고 관리 가능한 단위인 partition으로 나누는 기능입니다. 각 partition은 독립 이름과 저장 속성을 가질 수 있고, 애플리케이션은 하나의 테이블처럼 접근합니다.
Range
VALUES LESS THAN 상한값 기준. 상한값은 미만입니다.
Interval
Range의 확장. transition point 이후 INSERT 시 필요한 interval partition이 자동 생성됩니다.
List
명시적 값 목록 기준. 예외값 처리를 위해 DEFAULT partition을 둘 수 있습니다.
Hash
Oracle 내부 해시로 분산. 2의 거듭제곱은 권장될 수 있으나 필수라고 설명하지 않습니다.
Composite 지원 조합 요약
버전/계열조합
8iRange-Hash
9iRange-List
11g+Range-Range, List-Hash, List-List, List-Range
11g+ / 19cInterval-Range, Interval-Hash, Interval-List
19c 문법은 PARTITION BY { HASH | RANGE [ INTERVAL ] | LIST } 다음에 SUBPARTITION BY 절을 붙이는 구조로 설명할 수 있습니다.
Composite Range-Hash 이미지
SALES
├─ P_2026_H1 by RANGE(sales_date)
│  ├─ SP_H1_1 by HASH(customer_id)
│  └─ SP_H1_2 by HASH(customer_id)
└─ P_2026_H2 by RANGE(sales_date)
   ├─ SP_H2_1 by HASH(customer_id)
   └─ SP_H2_2 by HASH(customer_id)

  
DDL 예시
CREATE TABLE sales_interval (
  sales_id NUMBER, sales_date DATE, amount NUMBER
)
PARTITION BY RANGE (sales_date)
INTERVAL (NUMTOYMINTERVAL(1, 'MONTH')) (
  PARTITION p_before_2026 VALUES LESS THAN (DATE '2026-01-01')
);

CREATE TABLE sales_comp (
  sales_id NUMBER, sales_date DATE, customer_id NUMBER, amount NUMBER
)
PARTITION BY RANGE (sales_date)
SUBPARTITION BY HASH (customer_id)
SUBPARTITIONS 4 (
  PARTITION p_2026_h1 VALUES LESS THAN (DATE '2026-07-01'),
  PARTITION p_2026_h2 VALUES LESS THAN (MAXVALUE)
);

CREATE TABLE sales_interval_hash (
  sales_id NUMBER, sales_date DATE, customer_id NUMBER, amount NUMBER
)
PARTITION BY RANGE (sales_date)
INTERVAL (NUMTOYMINTERVAL(1, 'MONTH'))
SUBPARTITION BY HASH (customer_id)
SUBPARTITIONS 4 (
  PARTITION p0 VALUES LESS THAN (DATE '2026-01-01')
);

  
운영 체크
Global Partitioned Index
Global index 전체에는 nonpartitioned global index도 포함됩니다. 하지만 global partitioned index는 인덱스 파티션 키가 인덱스 컬럼의 left prefix인 prefixed 구조로 설명하는 것이 정확합니다.
Interval partition
자동 생성 partition 이름은 시스템 생성 이름일 수 있습니다. USER_TAB_PARTITIONS로 실제 이름, high value, interval 여부를 확인하세요.
PMOP와 Global Index
DROP/TRUNCATE 등 partition maintenance operation은 global index를 UNUSABLE로 만들 수 있으므로 UPDATE INDEXES / UPDATE GLOBAL INDEXES와 비용을 검토하세요.
