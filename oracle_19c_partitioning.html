1. 파티셔닝 핵심 개념

테이블을 Partition으로 나누고, Partitioning Key로 행의 위치를 결정하며, SQL 실행 시 Partition Pruning으로 불필요한 Partition을 제외합니다.

ORACLE DATABASE 19c
01Partitioned Table

테이블을 더 작은 단위인 Partition으로 나눕니다. 각 Partition은 고유 이름과 선택적 저장 속성을 가질 수 있습니다.

02Partitioning Key

하나 이상의 컬럼으로 구성되며, 주어진 행이 위치할 Partition을 결정합니다.

03Partition Pruning

Optimizer가 불필요한 Partition을 Partition Access List에서 제외합니다.

Partition Maintenance Operations

5. 인덱스와 파티션 운영 영향
Local/Global을 문법으로 암기하기보다, 유지보수 시 서비스 영향 차이를 이해합니다.

    

    


    

      참고: 파티션 인덱스 유형 상세 내용 보기
      

        
본 교육에서 모두 설명하지 않더라도, 파티션 인덱스 설계 시 참고할 수 있도록 유형과 특징을 남겨둔 영역입니다.

        

          

            
Local Prefixed Index

            
인덱스의 선두 컬럼이 테이블 파티션 키로 시작하는 Local Index입니다. 파티션 키 조건과 인덱스 조건을 함께 사용할 때 접근 범위를 이해하기 쉽습니다.

            
CREATE INDEX ix_sales_lp
ON sales_range (sales_date, customer_id)
LOCAL;

          


          

            
Local Nonprefixed Index

            
Local Index이지만 인덱스 선두 컬럼이 파티션 키로 시작하지 않습니다. 파티션 키 없는 조회에서는 여러 인덱스 파티션을 탐색할 수 있습니다.

            
CREATE INDEX ix_sales_lnp
ON sales_range (customer_id)
LOCAL;

          


          

            
Global Nonpartitioned Index

            
테이블 파티션 경계와 독립적인 하나의 전체 인덱스 구조입니다. 파티션 키가 없는 고유 조회 등에 사용할 수 있으나 파티션 DDL의 영향을 검토해야 합니다.

            
CREATE UNIQUE INDEX ux_sales_id
ON sales_range (sales_id)
GLOBAL;

          


          

            
Global Partitioned Index

            
Global Index 자체를 별도의 기준으로 파티셔닝합니다. 테이블 파티션과 인덱스 파티션의 경계가 반드시 일치하지는 않습니다.

            
CREATE INDEX ix_sales_gp
ON sales_range (customer_id)
GLOBAL PARTITION BY HASH (customer_id)
PARTITIONS 4;

          

        


        

          주의: Local/Global, Prefixed/Nonprefixed만으로 성능을 단정할 수 없습니다.
          주요 SQL 조건, 고유성 요구사항, 파티션 유지보수 방식, 인덱스 크기와 실제 실행계획을 함께 검토해야 합니다.
        

      

    

  


  

    
6. 서비스 적용 전 체크리스트

    

      
✓ 실제 주요 조회 조건과 파티션 키가 일치하는가?
✓ 날짜 조건을 >= 시작 AND < 종료 형태로 작성했는가?

      
✓ DATE/NUMBER 컬럼에 문자열을 직접 비교하지 않는가?
✓ 컬럼에 함수 적용 시 실행계획과 pruning을 확인했는가?

      
✓ 파티션 키 없는 조회를 지원할 인덱스가 있는가?
✓ 오래된 파티션 제거 시 Global Index 영향을 검토했는가?

      
✓ 배치·온라인 트래픽 시간대 충돌을 검토했는가?
✓ 적용 전 라이선스와 운영 정책을 담당자와 확인했는가?
