# 데이터 모델링

- **트랙**: B · DB 운영(DBA)
- **레벨**: L2
- **상태**: **운영 중** ✅
- **대상**: 스키마를 설계·리뷰하는 개발자 / 운영 DBA
- **선수과정**: [SQL 기초](../foundation/sql-foundation.md) · **다음**: [고성능 DB 설계](02-highperf-db-design.md)
- **틀(골격)**: 아래 **5장 목차**(이론 → 개념 → 논리 → 물리 → 모델링 이야기)를 학습자료 골격으로 채택.
- **재사용 우선**: 실습은 성능진단 소모임/SQL 기초의 기존 랩을 우선 재사용(메뉴 `data-target`을 기존 패널 id로 연결), 모델링 고유 영역만 신규 제작.
- **목표**: 업무 요건을 **개념→논리→물리** 모델로 단계적으로 옮기고, 정규화/반정규화·키·이력 등 설계 판단을 근거 있게 내린다.

범례: ♻️ 기존 랩 재사용 · 🆕 신규 제작 · 🔗 다른 과정(고성능 DB 설계) 랩 연계

---

## 1장. 데이터 모델링 이론
- **1.1 데이터 모델링이란**: 모델링의 정의·목적, 추상화 수준(개념/논리/물리), 좋은 모델의 조건(완전성·중복배제·업무규칙 반영)
- **1.2 ER 모델 구성 요소**: 엔티티(Entity) / 속성(Attribute) / 관계(Relationship) / 식별자, 표기법(IE·바커), 카디널리티·선택성
- **1.3 관계형 데이터 모델 이론**: 릴레이션·튜플·도메인, 키(후보/기본/대리/외래), 관계대수 개념, 무결성 규칙(개체·참조)
- 🧪 **랩**: **ERD 뷰어 🆕** — 엔티티·속성·관계·식별자/카디널리티를 인터랙티브로 해부(샘플 모델 위에서 구성요소 하이라이트)

## 2장. 개념 모델링
- **2.1 데이터 모델링 접근방법**: 하향식(업무→엔티티) vs 상향식(현행 데이터→통합), 주제영역(Subject Area) 분할
- **2.2 개념 모델링**: 핵심 엔티티·관계 식별, 업무 규칙 정리, 개념 ERD 작성(상세 속성 이전 단계)
- 🧪 **랩**: **개념 ERD 스케치 🆕(소형)** — 업무 시나리오 → 핵심 엔티티/관계 도출 연습(보기 선택형)

## 3장. 논리 모델링
- **3.1 논리 모델링이란**: 개념→논리 상세화, DBMS 독립적 산출물, 정규화의 위치
- **3.2 엔티티 정의 및 상세화**: 엔티티 도출·검증, 슈퍼/서브타입, 엔티티 통합/분리 판단
- **3.3 관계 도출 및 정의**: 식별/비식별 관계, 1:1·1:N·M:N 해소(교차 엔티티), 자기참조·순환관계
- **3.4 속성 도출 및 정의**: 원자성, 파생/유도 속성, 도메인 정의, NULL 의미
- **3.5 데이터 표준화**: 표준 단어/용어/도메인, 네이밍 규칙, 표준 준수 검증
- **정규화**(논리 모델링의 핵심): 함수종속, 1NF~BCNF, 이상현상(삽입·갱신·삭제), 반정규화 트레이드오프
- 🧪 **랩**:
  - **정규화 변환기 🆕(핵심)** — 비정규 → 1·2·3NF·BCNF 단계 분해, 함수종속/이상현상 데모, 반정규화 비용 비교 *(→ 고성능 DB 설계가 이 랩을 🔗 공유)*
  - **데이터 표준화 체커 🆕(소형)** — 표준 단어·도메인·네이밍 규칙 적용/위반 진단

## 4장. 물리 모델링
- **4.1 물리 모델링이란**: 논리→물리 변환(DBMS 종속), 성능·저장·운영 요건 반영
- **4.2 테이블 설계**: 엔티티→테이블, 슈퍼/서브타입 물리화(단일/분리/통합), 행 길이
- **4.3 관계 설계**: 관계→FK, 식별/비식별 물리화, M:N 교차 테이블
- **4.4 컬럼 설계**: 데이터 타입 선택, NULL 설계, 기본값, 컬럼 순서
- **4.5 데이터 무결성 설계**: PK/FK/UK/CHECK/NOT NULL, 선언적 vs 애플리케이션 무결성
- **4.6 성능을 고려한 데이터 구조**: 반정규화 물리 적용, 집계/이력 구조, 파티셔닝 후보 식별 *(심화 운영은 🔗 고성능 DB 설계)*
- **4.7 물리 설계 / 4.8 인덱스 설계 / 4.9 파티션 설계**: 모델 관점의 기본 원칙(결합 인덱스 컬럼 순서·PK 인덱스, 파티션 키 선택) — **저장구조·라이프사이클 운영은 다음 과정**
- 🧪 **랩**:
  - 인덱스 시뮬레이터 ♻️`panel-index` — 결합 인덱스 컬럼 순서·탐색 기본 개념
  - 설계 안티패턴(형변환 유발 타입 등) — 플랜 진단 ♻️`panel-plan-diag` 일부 재사용
  - 인덱스 설계 실험실 / 파티션 라이프사이클 / 설계 검토기 🔗 (고성능 DB 설계에서 심화)

## 5장. 모델링 이야기 (실무 케이스)
- 케이스 모음(읽기 자료 + 미니 퀴즈): 고객의 정의 / 개인정보 데이터 구조와 암호화 / 공통코드 설계 / 시스템 사용자·프로그램 관리 / 주소 코드·관리 / 과도한 엔티티 통합 / 데이터 통합 vs 구조 통합 / 어디까지 일반화할 것인가 / 원칙과 현실 사이 / 인조 식별자 사용 시점 / 다양한 업무발생의 인조 식별자 / 업무 흐름에 따른 설계 / 매년 변경되는 소득공제 항목 / **점 이력 → 선분 이력** / 관계가 없을까(이력관리) / 심리검사 종류별 관리 / 문자열 데이터 분리(수직분할) / 논리모델이 제공된다면 / 엔티티 정의의 명확성 / 참조무결성 / 순환관계 컬럼 추가 / 인덱스 설계
- 🧪 **랩**:
  - **선분 이력 변환 시각화 🆕(소형)** — 점 이력 → 선분 이력(시작/종료일) 변환과 조회 차이
  - **식별자 설계 비교 🆕(소형)** — 자연키 vs 인조(대리)키 트레이드오프
  - 수직분할 before/after — 개념 설명 + 인덱스 시뮬레이터 ♻️`panel-index` 보조

## 범위 경계 (다음 레벨로 미룸 — 고성능 DB 설계 L3)
- **물리 저장구조·운영**: 테이블스페이스/세그먼트/익스텐트, HWM·단편화, 행 이전, shrink/reorg
- **파티션 라이프사이클 운영**: Interval 자동 생성·만료 DROP/TRUNCATE·Exchange 적재·프루닝 확인
- **통계정보 관리**: 옵티마이저 통계·히스토그램·확장통계 수집/운영
- **인덱스 성능 설계**: 쿼리 집합 기반 최적 인덱스·순서 결정, 과다 인덱스 DML 패널티(인덱스 설계 실험실)
- ⇒ L2(데이터 모델링)는 **모델 산출물·설계 원칙**까지, L3(고성능 DB 설계)는 **성능·운영 심화**.

## 경계/소유권 메모 (확인 필요)
- **정규화 변환기**는 본 과정(논리 모델링)에서 신규 제작하고, [고성능 DB 설계](02-highperf-db-design.md) 세션 1은 이 랩을 🔗 재사용하도록 정리 권장(중복 제작 방지).
- 고성능 DB 설계 세션 1(데이터 모델링&정규화)은 본 과정과 겹치므로, L3에서는 정규화 **요약 + 물리화/성능 관점**으로 축소 권장.
