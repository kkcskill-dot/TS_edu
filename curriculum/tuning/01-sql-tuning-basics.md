# SQL 튜닝 기본

- **트랙**: A · DB 튜닝
- **레벨**: L2
- **상태**: **기획 완료** (구현 대기)
- **대상**: SQL을 작성할 수 있고, 느린 쿼리를 스스로 진단·개선하려는 개발자/운영자
- **선수과정**: [SQL 기초](../foundation/sql-foundation.md) · **다음**: [SQL 전문가](02-sql-advanced.md)
- **틀(골격)**: 「친절한 SQL 튜닝」의 **7장 + 부록** 구성을 학습자료 골격으로 채택.
- **재사용 우선**: 실습은 성능진단 소모임의 기존 랩을 최대한 재사용(메뉴 `data-target`을 기존 패널 id로 연결), 부족분만 신규 제작.

범례: ♻️ 소모임 랩 재사용 · 🆕 신규 제작 · 🔗 다른 과정 랩 연계

## 1장. SQL 처리 과정과 I/O
- **1.1 SQL 파싱과 최적화**: 구조적·집합적·선언적 질의언어 / SQL 최적화 / SQL 옵티마이저 / 실행계획과 비용 / **옵티마이저 힌트**
- **1.2 SQL 공유 및 재사용**: 소프트 파싱 vs 하드 파싱 / 바인드 변수의 중요성
- **1.3 데이터 저장 구조 및 I/O**: SQL이 느린 이유 / 저장 구조 / 블록 단위 I/O / 시퀀셜 vs 랜덤 / 논리적 vs 물리적 I/O / Single vs Multiblock I/O / Table Full Scan vs Index Range Scan / 캐시 탐색
- 🧪 **랩**: 실행 계획 시각화 ♻️`panel-explain` · 바인드 변수 & 파싱 ♻️`panel-bind-parse` · **힌트 실습 🆕**

## 2장. 인덱스 기본
- **2.1 인덱스 구조 및 탐색**: 미리 보는 인덱스 튜닝 / 인덱스 구조 / 수직적·수평적 탐색 / 결합 인덱스 구조와 탐색
- **2.2 인덱스 기본 사용법**: 인덱스를 사용한다는 것 / Range Scan 불가 사유 / 더 중요한 사용 조건 / 소트 연산 생략 / ORDER BY·SELECT-List 컬럼 가공 / 자동 형변환
- **2.3 인덱스 확장 기능**: Range / Full / Unique / Skip / Fast Full Scan / Range Scan Descending
- 🧪 **랩**: 인덱스 시뮬레이터 ♻️`panel-index`(B-tree 수직/수평·결합) · 플랜 진단(기초) ♻️`panel-plan-diag`(형변환·컬럼가공)

## 3장. 인덱스 튜닝
- **3.1 테이블 액세스 최소화**: 랜덤 액세스 / 클러스터링 팩터 / 손익분기점 / 컬럼 추가 / 인덱스만 읽고 처리 / IOT / 클러스터 테이블
- **3.2 부분범위 처리 활용**: 부분범위 처리·구현 / OLTP 성능개선 원리
- **3.3 인덱스 스캔 효율화**: 액세스 vs 필터 조건 / 선행 컬럼 비등치 비효율 / BETWEEN→IN-List / Skip Scan / LIKE·BETWEEN 범위 / 함수호출부하 해소
- **3.4 인덱스 설계**: 두 가지 선택 기준 / 결합 인덱스 선택도 / 중복 인덱스 제거 / 설계도 작성
- 🧪 **랩**: 인덱스 시뮬레이터 ♻️`panel-index` · **클러스터링 팩터/손익분기점 시각화 🆕(소형)** · 인덱스 설계 🔗(고성능 DB 설계 과정의 인덱스 설계 실험실 연계)

## 4장. 조인 튜닝
- **4.1 NL 조인**: 메커니즘 / 실행계획 제어 / 수행과정·튜닝포인트·확장 메커니즘
- **4.2 소트 머지 조인**: SGA vs PGA / 메커니즘 / 주용도 / 제어
- **4.3 해시 조인**: 메커니즘 / 빠른 이유 / 대용량 Build Input / 제어 / 조인 메소드 선택 기준
- **4.4 서브쿼리 조인**: 서브쿼리 변환 / 서브쿼리·뷰·스칼라 서브쿼리 조인
- 🧪 **랩**: 조인 비교 실험실 ♻️`panel-join-lab`(NL/소트머지/해시 비용) · 조인 문법 실습실 ♻️`panel-join-syntax-lab` · 서브쿼리/뷰 머지 ♻️`panel-plan-adv`(view_merge 시나리오)

## 5장. 소트 튜닝
- **5.1 소트 연산 이해**: 수행 과정 / 소트 오퍼레이션
- **5.2 소트가 발생하지 않도록**: Union vs Union All / Exists 활용
- **5.3 인덱스로 소트 생략**: Sort Order By 생략 / Top-N / 최소·최대값 / 이력 조회 / Sort Group By 생략
- **5.4 Sort Area 절약**: 소트 데이터 줄이기 / Top-N 소트 부하 / 분석함수 Top-N
- 🧪 **랩**: **소트 튜닝 실습 🆕(소형)**(소트 발생/생략 before-after) · 실행 계획 시각화 ♻️`panel-explain`

## 6장. DML 튜닝
- **6.1 기본 DML 튜닝**: 영향 요소 / DB Call과 성능 / Array Processing / 인덱스·제약 해제 / 수정가능 조인 뷰 / MERGE
- **6.2 Direct Path I/O**: Direct Path I/O·Insert / 병렬 DML
- **6.3 파티션 활용 DML**: 테이블·인덱스 파티션 / 대량 UPDATE·DELETE·INSERT 튜닝
- **6.4 Lock과 동시성 제어**: 오라클 Lock / 트랜잭션 동시성 / 채번 방식별 INSERT 성능
- 🧪 **랩**: 락 & 동시성 샌드박스 ♻️`panel-locks` · 파티션 🔗(고성능 DB 설계의 파티션 라이프사이클) · Array/Call 개념 ♻️`panel-bind-parse` 보조

## 7장. SQL 옵티마이저
- **7.1 통계정보와 비용**: 선택도·카디널리티 / 통계정보 / 비용 계산 원리
- **7.2 옵티마이저 이해**: 종류·모드 / 영향 요소 / 한계 / 개발자의 역할 / 공부 방법
- 🧪 **랩**: 플랜 진단(기초) ♻️`panel-plan-diag`(통계·카디널리티 오차) · 적응형 최적화 ♻️`panel-adaptive`(통계 피드백)

## 부록. SQL 분석 도구
- 실행계획 확인 / AutoTrace / SQL 트레이스 / DBMS_XPLAN / 실시간 SQL 모니터링 / V$SQL
- 🧪 **랩**: SQL Trace·TKPROF ♻️`panel-trace` · 실행 계획 시각화 ♻️`panel-explain`(DBMS_XPLAN)
