카디널리티

CBO는 통계로 경로를 고른다 — 선택도·카디널리티 계산부터
접근경로·조인·예상 vs 실측·플랜 변경·힌트까지.

CBO 원리
비용이 최소인 경로를 고른다

옵티마이저는 여러 실행계획 대안을 만들고, 각 경로의 I/O + CPU를 비용(Cost)으로 환산해 최솟값을 선택한다.

비용 공식의 변수 = 통계 정보. 통계가 틀리면 비용이 틀리고, 비용이 틀리면 플랜이 틀린다.
학습 목표
  • 통계 → 선택도 → 카디널리티 → 비용의 연쇄
  • DBMS_XPLAN으로 실측 플랜 추출
  • 트리 들여쓰기로 연산 순서 판독
  • E-Rows vs A-Rows 오차로 병목 색출
  • 플랜 변경(Regression) 대응
통계 정보
비용 공식에 채워지는 변수들
구분핵심 통계
테이블NUM_ROWS, BLOCKS, AVG_ROW_LEN
컬럼NUM_DISTINCT, HISTOGRAM, LOW/HIGH_VALUE, NUM_NULLS
인덱스BLEVEL, LEAF_BLOCKS, CLUSTERING_FACTOR
클러스터링 팩터(CF)
  • 인덱스 정렬 ↔ 테이블 물리 정렬의 일치도
  • CF ≈ 블록 수 → 좋음(적은 랜덤 I/O)
  • CF ≈ 행 수 → 나쁨(랜덤 I/O 폭증)
  • 같은 인덱스라도 CF가 비용을 가른다
핵심 공식
선택도 & 카디널리티
선택도 = 1 / NUM_DISTINCT
카디널리티(E-Rows) = NUM_ROWS × 선택도
의미
  • "조건을 적용하면 전체 중 몇 %가 남는가"
  • 고유값 많을수록(NDV↑) 선택도↓ → 적은 행
  • 이 추정이 접근경로·조인 선택을 좌우
  • NULL·범위·결합조건은 공식이 더 복잡
실전 대입
통계가 틀리면 25만 vs 1천

WHERE grade='VIP' · NUM_ROWS=1,000,000 · NDV=4

1/4=0.25 → 100만 × 0.25 = 25만 예측옵티마이저: "25만이면 Full Scan"
실제 VIP는 0.1%(1천 건). 히스토그램이 없으면 균등분포 가정 → 심각한 오판.
왜 균등 가정?
  • 히스토그램 없으면 4종이 각 25%라 가정
  • 편향 분포(99% vs 1%)를 모름
  • 해결: 해당 컬럼에 히스토그램 수집
  • method_opt=>'FOR COLUMNS SIZE 254 GRADE'
통계 노후화
STALE 통계와 자동 수집

STALE 위험

실제 1천만인데 통계는 100건 → 대량 쿼리를 가볍게 오판.

자동 수집

야간 윈도(기본 22:00) DBMS_STATS.GATHER_*가 STALE 객체 갱신.

STALE 판정: 전체의 10% 이상 DML 변경 시 해당 객체 통계가 STALE로 마킹.
진단 · 수동 수집
  • DBA_TAB_STATISTICS: STALE_STATS, LAST_ANALYZED
  • DBA_TAB_COL_STATISTICS: 히스토그램·버킷
  • 긴급: GATHER_TABLE_STATS(..., cascade=>TRUE)
  • AUTO_SAMPLE_SIZE + FOR ALL COLUMNS SIZE AUTO
실측 플랜 추출
DBMS_XPLAN — 예상이 아닌 실측
-- 메모리 커서: 최근 실행의 실측치 SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR( 'sql_id', NULL, 'ALLSTATS LAST +COST +BYTES +NOTE')); -- 과거(메모리에서 밀려남): AWR 복원 SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_AWR('sql_id'));
옵션 · 플랜 변경 추적
  • ALLSTATS LAST = 최근 실행 실측(A-Rows·Buffers)
  • 전제: /*+ GATHER_PLAN_STATISTICS */
  • EXPLAIN PLAN은 바인드·캐시 반영 안 됨(예상만)
  • 같은 SQL_ID에 PLAN_HASH_VALUE 여러 개 = 플랜 변경
플랜 해독
트리 들여쓰기 3규칙
  • 가장 깊은 곳(오른쪽으로 밀린 노드)이 먼저 실행
  • 같은 깊이면 위가 먼저
  • 자식이 Row Source를 반환하면 부모가 입력으로 받아 구동
읽기 팁
  • 안쪽 → 바깥, 위 → 아래 순으로 따라간다
  • * 표시 = Predicate(조건) 있는 노드
  • 하단 Predicate Information에서 access/filter 확인
접근 경로
스캔 방식 6종
방식특징
TABLE ACCESS FULLHWM까지 다중블록 — 대량/소형에 유리
INDEX UNIQUE SCANPK/유니크 = 정확히 1건
INDEX RANGE SCAN범위(BETWEEN/LIKE 'A%') — 소량 고속
INDEX FULL SCAN리프 순서대로(단일블록) — 정렬 생략
INDEX FAST FULL SCAN다중블록·정렬X — Index Only/병렬
INDEX SKIP SCAN선두 컬럼 없을 때(NDV 작아야 유리)
갈림길
  • 소량 → 인덱스, 10~15% 초과 → FTS
  • Full vs Fast Full: 단일블록(정렬보장) vs 다중블록(정렬X)
  • Skip Scan: 선두 NDV 적으면 OK, 많으면 FTS만 못함
  • Index Only = 테이블 접근 생략(커버링)

진단의 급소
E-Rows vs A-Rows
E-Rows × Starts ≈ A-Rows이 균형이 무너진 라인 = 옵티마이저 오판 = 병목

Starts

그 노드가 실제 구동된 횟수(NL 하위는 반복).

Buffers

논리적 I/O — 클수록 자원 폭식.

오차 3대 원인
  • 통계 노후화 — NUM_ROWS/NDV가 현실과 괴리
  • 히스토그램 부재 — 편향 분포에 균등 가정
  • 컬럼 상관관계 — A=1 AND B=2를 독립 가정
케이스 A
통계 노후화 → NL 오판(45M Buffers)
| Id | Operation | Starts |E-Rows|A-Rows|Buffers| | 1 | NESTED LOOPS | 1 | 1 | 1 | 45M | | 4 | TABLE ACCESS(ORD) | 1 | 1 | 25M | 45M | |* 5 | INDEX RANGE SCAN | 1 | 1 | 25M | 200K |
진단
  • E-Rows 1 예측 → NL 선택
  • 실제 A-Rows 25M → 200K 인덱스 + 45M 테이블 랜덤 I/O
  • 원인: TB_ORDER 통계 노후화
  • 조치: 통계 갱신 → HASH JOIN 유도
케이스 B
히스토그램 부재 → 25만 vs 85
SELECT * FROM tb_log WHERE status='ERROR'; -- E-Rows 250K vs A-Rows 85
ACTIVE99.5%
ERROR0.01%
분석
  • NDV=4·NUM_ROWS=100만 → 100만/4 = 25만 균등 가정
  • 실제 ERROR는 0.01%(85건)의 희소값
  • 오판이 후속 조인까지 연쇄
  • 해결: FOR COLUMNS SIZE 254 STATUS 히스토그램
케이스 C
상관 서브쿼리 → Starts 500
|* 5 | TABLE ACCESS FULL TB_SALARY |Starts 500|Buffers 800K| -- 메인 500행마다 서브쿼리 풀스캔 반복 -- 500 × 1,600블록 = 800,000 논리 I/O
해결
  • 상관 서브쿼리가 행마다 반복 = Starts 폭증
  • 인라인 뷰 + 조인으로 Subquery Unnesting
  • 또는 ROW_NUMBER() OVER(PARTITION BY) 1회 스캔
  • 플랜의 FILTER 연산 = 상관 서브쿼리 신호

  • 근본: 해당 테이블 통계 고정(LOCK_TABLE_STATS)

묵시적 형변환 → 인덱스 무력화
-- Predicate: TO_NUMBER("MEMBER_NO") = 2026001234 -- 컬럼이 VARCHAR2인데 숫자로 비교 → 좌변에 함수 → 인덱스 불가 → FTS(24500 Buffers) setInt(1, memberNo) // 🚨 숫자 전달 setString(1, String.valueOf(memberNo)) // ✔ 문자 전달
교훈
  • 좌변 컬럼에 함수/형변환 = 인덱스 무력화
  • 바인드 타입을 컬럼 타입에 일치
  • 증거는 플랜 Predicate 섹션의 TO_*()
  • 수정 후 DISPLAY_CURSOR로 재검증
한 장 정리
3회차 핵심
  • CBO는 통계 → 선택도 → 카디널리티 → 비용으로 선택
  • 선택도=1/NDV, 편향 분포엔 히스토그램
  • 실측은 DISPLAY_CURSOR(ALLSTATS LAST)
  • 접근경로 6종·조인 3종을 데이터 규모·인덱스로
  • 모든 진단의 급소 = E-Rows × Starts ≈ A-Rows
평가 포인트
  • Starts 폭증 = NL 오선택 → HASH 유도
  • Soft 99.8% + Hit 72% → I/O 이벤트·인덱스 점검
  • 선두 컬럼 없으면 Skip Scan vs FTS
  • 플랜 강제는 통계 최신화로 갈음
