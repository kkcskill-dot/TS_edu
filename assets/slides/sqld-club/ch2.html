성능 모델링
성능 데이터 모델링 — 개요 & 절차

성능은 장비 증설·쿼리 튜닝만으로 한계가 있고, 근본 병목은 잘못된 데이터 모델에서 나옵니다. 설계 단계에 성능을 반영해야 후반 재작업을 줄입니다.

  • ① 정규화로 이상현상 제거
  • ② 용량 산정 · 트랜잭션 유형 파악
  • ③ 반정규화 검토
  • ④ 이력 / PK·FK / 슈퍼·서브타입 조정
  • ⑤ 성능 관점 모델 검증
포인트
  • 성능 모델링은 분석/설계 전반에 수행
  • 늦게 손대면 구조 전체 재작업 비용
정규화
정규화 — 왜? & 함수 종속

중복을 제거해 이상현상(Anomaly)을 없애고 데이터 무결성을 높이는 과정. 기준은 함수 종속(A→B: A가 정해지면 B가 하나로 결정).

삽입 이상

불필요 데이터 없이는 입력 불가.

갱신 이상

중복 일부만 수정→불일치.

삭제 이상

지우면 필요 정보까지 손실.

핵심
  • 정규화 ↑ → 중복 ↓, 무결성 ↑
  • 대신 조인 ↑ → 조회 성능 ↓ 가능
  • 정규화는 논리 모델링에서 수행
정규화
제1정규형 (1NF) — 원자값

모든 속성은 하나의 원자값만 가져야 한다. 반복 그룹·다중값 제거.

회원ID이름취미(위배)
U01김철수독서, 등산
해소: 취미를 행으로 분리하거나 취미 테이블(1:M)로 분리.
판별
  • 한 칸에 콤마로 여러 값? → 1NF 위배
  • 유사 컬럼 반복(취미1, 취미2)? → 1NF 위배
정규화
제2정규형 (2NF) — 부분 종속 제거

복합키의 일부에만 종속되는 일반 속성(부분 함수 종속)을 분리.

주문번호(PK)상품코드(PK)수량상품명
O01P012노트북
O02P015노트북
상품명은 상품코드에만 종속 → 상품 테이블로 분리.
전제
  • 2NF는 복합키일 때만 의미(단일키면 자동 2NF)
  • 부분 종속 = 키 일부 → 비키 속성 결정
정규화
제3정규형 (3NF) — 이행 종속 제거

3NF: 키가 아닌 속성 간 종속(이행 종속 A→B→C)을 제거.

사원ID(PK)부서코드부서명
E01D1영업
부서명은 사원ID→부서코드→부서명의 이행 종속 → 부서 테이블로 분리.
한 줄 요약
  • 1NF=원자값, 2NF=부분종속, 3NF=이행종속
  • "이행 종속 제거는 몇 정규형?" → 3NF
  • 결정자가 후보키가 아니면 → BCNF로 추가 분해(다음 장)
정규화
BCNF — 모든 결정자는 후보키여야 한다

BCNF(보이스-코드 정규형)는 3NF를 더 엄격하게 한 것. 어떤 속성을 결정하는 결정자가 후보키가 아니면 위배.

학생과목교수
김DB이교수
박DB이교수
규칙: 교수 → 과목(교수가 과목을 결정). 후보키는 (학생,과목)·(학생,교수)인데 교수는 후보키가 아님 → 3NF는 만족해도 BCNF 위배.
해소: (학생,교수) + (교수,과목) 두 테이블로 분해.
핵심
  • BCNF ⊃ 3NF (더 강한 조건)
  • 결정자(determinant)가 모두 후보키면 BCNF
  • 후보키가 여럿이고 서로 겹칠 때 주로 발생
  • 3.5정규형이라고도 부름
반정규화
반정규화 — 성능을 위한 의도적 중복
대상기법
테이블병합 · 분할(수평/수직) · 추가(중복·통계·이력)
컬럼중복 컬럼 · 파생 컬럼 · 이력 PK 추가
관계중복 관계 추가
순서: 먼저 정규화 → 측정된 성능 문제에 한해 반정규화(무분별 금지).
트레이드오프
  • 조회 성능 ↑ ↔ 무결성·갱신 비용 ↑·저장 ↑
  • 처리 성능이 떨어지는 경우에 수행
  • 중복관계 추가는 무결성 영향 없는 유일한 기법
슈퍼/서브타입
슈퍼/서브타입 물리 변환 3가지
방식내용유리한 경우
One To One
(서브타입)		슈퍼+서브 각각 테이블서브 속성 많고 개별 처리
Plus
(슈퍼+서브)		슈퍼 1 + 서브별 테이블서브별 처리 + 공통 조회
Single
(All in One)		한 테이블로 통합(+구분컬럼)전체 일괄 조회 잦음
선택 기준
  • 데이터량·트랜잭션 접근 패턴으로 결정
  • 통합 조회 多 → Single
  • 개별 처리 多 → OneToOne
  • Single은 NULL 컬럼 많아질 수 있음
대용량 처리
파티셔닝 (Partitioning)

대용량 테이블은 인덱스 트리가 깊어져 성능이 저하됩니다. 논리적으로 1개 테이블이지만 물리적으로 여러 테이블스페이스에 분산 저장.

종류기준예
RANGE연속 값 범위(가장 많이 씀)월별(2026-01…)
LIST특정 값(코드)지점(서울·부산)
HASH해시 함수 균등 분할치우침 없을 때
암기
  • RANGE = 날짜·범위(최다)
  • LIST = 코드값
  • HASH = 시스템 균등 분할(관리 어려움)
분산 DB
분산 데이터베이스의 투명성

여러 곳에 흩어진 DB를 하나의 논리 DB처럼 사용. 사용자는 분산 사실을 몰라도 됩니다(투명성).

분할 / 위치

분할 여부·물리적 위치를 몰라도 됨.

중복 / 병행

복제 여부·동시 실행 몰라도 일관성 유지.

장애 / 지역사상

일부 장애에도 동작, 지역 DBMS 무관.

적용 기법
  • 위치 분산 · 분할 분산(수평/수직)
  • 복제(Replication) 분산 — 조회 성능 ↑(최다)
