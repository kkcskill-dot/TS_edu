제 1과목. 데이터 모델링의 이해

건물을 짓기 전 설계도가 필요하듯, 데이터베이스를 구축하기 전 모델링이 필요합니다.
시스템의 뼈대를 잡는 데이터 모델링의 근본 개념을 다룹니다.

1과목 · 데이터 모델링
데이터 모델링의 3단계 🏆
데이터 모델링은 밑그림을 그리는 것부터 실제 건물을 올리는 것까지 추상화 수준(포괄성)에 따라 3단계로 점진적으로 진행됩니다.
단계특징설명 및 산출물
1. 개념적 모델링
(Conceptual)		 추상화 수준 최고
업무 중심적 포괄성		 전사적 아키텍처(EA) 수립 시 주로 사용합니다.
핵심 엔터티와 그들 간의 관계를 도출하는 최초 단계입니다.
산출물: 개략적인 ERD
2. 논리적 모델링
(Logical)		 재사용성 최고
정규화 수행 완료		 데이터 모델링의 꽃이자 핵심입니다.
테이블, 식별자, 일반속성 및 릴레이션을 정의합니다.
특징: 특정 DBMS에 종속되지 않습니다.
3. 물리적 모델링
(Physical)		 구체화 수준 최고
성능 고려 (HW)		 실제 데이터베이스(Oracle, MySQL 등)에 이식하는 단계입니다.
테이블스페이스, 인덱스, 파티셔닝 등 성능을 직접 고려합니다.
핵심 포인트
  • 시험 출제 1순위! 3단계의 순서와 특징을 명확히 기억해 두세요.
  • 개념적 -> 논리적 -> 물리적으로 갈수록 구체화됨을 강조합니다.
  • 정규화는 논리적 단계에서 수행합니다.
  • 특정 DBMS 종속은 오직 물리적 모델링뿐입니다.
1과목 · 데이터 모델링
엔터티 (Entity)의 6가지 특징

엔터티는 엑셀의 '시트(Sheet)', DB의 '테이블(Table)'에 해당합니다.
엔터티로 도출되기 위해서는 다음 6가지 조건을 반드시 만족해야 합니다.

  • 1. 업무에서 필요로 하는 정보: 시스템 구축 영역에서 반드시 관리되어야 하는 정보 (예: 병원의 '환자', '의사')
  • 2. 유일한 식별자로 구별 가능: 각 인스턴스(행)를 고유하게 식별할 주식별자(PK)가 필수입니다.
  • 3. 2개 이상의 인스턴스 집합: 한 명의 고객만을 위해 '고객' 엔터티를 만들지 않습니다. 집합을 이뤄야 합니다.
  • 4. 반드시 속성(Attribute)을 가짐: 속성이 없는 엔터티는 빈 껍데기입니다. (최소 2개 이상)
  • 5. 업무 프로세스에 의해 이용됨: 만들어 놓고 안 쓰는 엔터티는 필요 없습니다. (CRUD 발생)
  • 6. 최소 1개 이상의 관계: 고립된 엔터티는 잘못 설계된 것입니다. (단, 공통코드/통계성 예외)
시험 단골 오답 노트
  • "고립된 엔터티는 좋은 설계다?" ➔ NO! 반드시 다른 엔터티와 관계를 맺어야 의미가 생깁니다.
  • "속성이 없는 엔터티도 존재할 수 있다?" ➔ NO! 아무 정보도 담지 못하는 테이블은 존재할 수 없습니다.
1과목 · 데이터 모델링
속성(Attribute)과 식별자(Identifier)

기본 속성

업무에서 처음부터 도출됨.
(이름, 가입일, 주소 등)

설계 속성

시스템 관리를 위해 새로 만듦.
(고객번호, 일련번호 등)

파생 속성

다른 속성에서 계산되어 파생됨.
(총주문금액, 평균점수 등)

주식별자(Primary Key)의 4대 특징 (시험 매우 단골)
1. 유일성: 인스턴스를 서로 고유하게 구별 (주민번호, 사번)
2. 최소성: 유일성을 보장하는 최소한의 속성 조합
3. 불변성: 한 번 지정된 값은 변하지 않아야 함
4. 존재성: 절대 NULL 값이 들어올 수 없음 (NOT NULL)
원자성의 원칙
  • 속성은 반드시 하나의 값(원자값)만 가져야 합니다.
  • 하나의 속성에 취미가 '독서, 수영'처럼 콤마로 들어가면 1차 정규화 대상입니다.
  • 파생 속성은 데이터 정합성 유지를 위해 가급적 적게 정의해야 성능에 유리합니다.

제 2과목. SQL 기본 및 활용

정규화와 성능 최적화

잘못된 테이블 설계가 부르는 데이터 꼬임(이상 현상)을 막는 '정규화' 과정과
반대로 조회 속도를 위해 룰을 깨는 '반정규화'를 다룹니다.

2과목 · 성능 모델링
제1·2정규형 (1NF, 2NF) 분해 과정
제1정규형 (1NF)모든 속성은 원자값을 가져야 한다.
회원ID (PK)이름취미 (원자성 위배)
U001김철수독서, 등산
제2정규형 (2NF)복합키의 일부에만 종속되는 일반 속성(부분 종속)을 분리한다.
주문번호(PK)상품코드(PK)수량상품명 (부분 종속)
O001P012노트북
O001P021마우스
O002P015노트북
분해(정규화)의 이유
  • 1NF 분해: 취미가 2개면 콤마 대신 데이터 행(Row)을 2개로 늘리거나, 별도 취미 테이블로 1:M 분리합니다.
  • 2NF 분해: `상품명`은 `주문번호`와 무관하게 `상품코드` 하나에만 종속됩니다. 노트북 이름이 바뀌면 여러 주문 건을 다 찾아 수정해야 하므로 상품 테이블을 분리해야 합니다.
2과목 · 성능 모델링
제3정규형 (3NF) 과 반정규화
제3정규형 (3NF)일반 속성끼리 서로 종속(이행적 종속)되는 것을 분리한다.
사번(PK)이름부서코드부서명 (이행적 종속)
1001김철수D01개발팀
1002이영희D01개발팀
반정규화 (De-normalization) 란?
정규화를 잘 해두면 조회 시 조인(JOIN)이 빈번하게 발생하여 성능이 느려질 수 있습니다. 조회 성능을 극대화하기 위해 데이터 무결성이 깨질 위험을 감수하고 데이터의 중복을 허용(테이블 병합, 컬럼 중복 등)하여 모델을 의도적으로 망가뜨리는 기법입니다.
이행적 종속 해소
  • 사번 ➔ 부서코드 ➔ 부서명 (A➔B➔C 종속)
  • `부서명`은 PK가 아닌 `부서코드`에 종속되므로 부서 테이블로 떼어냅니다.
반정규화 Trade-off
  • SELECT 조회 성능 상승
  • UPDATE, DELETE 성능 하락 (중복 데이터를 다 찾아야 함)
2과목 · 성능 모델링
보이스-코드 정규형 (BCNF)
BCNF (Boyce-Codd Normal Form)모든 결정자가 후보키(Candidate Key)가 되도록 테이블을 분리한다.
학생(PK)과목(PK)강사명 (결정자)
S001DB김교수
S002DB이교수
S001OS박교수
BCNF 위배 상황이란?
위 테이블에서 (학생, 과목)이 복합 PK입니다. 만약 한 강사가 오직 하나의 과목만 강의한다면, '강사명'이 '과목'을 결정하게 됩니다.
즉, 일반 속성(강사명)이 PK의 일부(과목)를 결정하는 결정자 함수 종속성이 발생하므로 강사 테이블을 따로 분리해야 합니다.
BCNF 핵심 요약
  • 3NF를 만족하면서, 모든 결정자가 후보키인 상태.
  • "강한 제3정규형" 이라고도 불립니다.
  • 일반 속성이 주식별자의 일부를 결정하는 역종속 현상을 해소합니다.

제 2과목. SQL 기본 및 활용

SQL 기본 (SELECT의 모든 것)

개발자가 매일 치는 SELECT 쿼리. 그 뒤에 숨겨진 진짜 실행 순서와
수많은 버그를 양산하는 NULL 데이터의 끔찍한 진실을 파헤칩니다.

2과목 · SQL 기본
SELECT 구문의 논리적 실행 순서 🏆
1. FROM -- 대상 테이블을 디스크에서 읽어온다 2. WHERE -- 조건에 맞는 행(Row)만 필터링한다 3. GROUP BY -- 남은 데이터를 그룹화하여 묶는다 4. HAVING -- 그룹화된 결과(집계)에서 필터링한다 5. SELECT -- 최종 화면에 출력할 컬럼을 추출한다 6. ORDER BY -- 화면에 뿌리기 직전, 결과를 정렬한다
실무·시험 최다 출제
  • Q: SELECT 절에서 만든 별칭(Alias)을 WHERE 절에서 쓸 수 없는 이유는?
  • A: 실행 순서상 WHERE(2번)가 SELECT(5번)보다 먼저 실행되기 때문에 별칭이 존재하는지조차 모릅니다!
  • 단, ORDER BY(6번)는 가장 마지막이므로 SELECT에서 만든 별칭을 쓸 수 있습니다.
2과목 · SQL 기본
NULL 데이터의 치명적 함정 🚨
명심하세요! NULL은 '0'이나 '빈칸'이 아닙니다. 아직 모르는 미지의 값(Unknown)입니다!
상황쿼리 예시 및 결과
사칙 연산100 + NULL = NULL
(연산 결과는 무조건 NULL로 오염됨)
비교 연산NULL = NULL ➔ UNKNOWN (거짓)
(반드시 IS NULL을 사용해야 함)
집계 함수SUM, AVG는 NULL이 포함된 행을 무시(제외)하고 계산함.
SELECT AVG(COMM) FROM EMP; -- 3명 중 1명만 50원이고 2명이 NULL이라면? -- 50 / 3명이 아니라, 50 / 1명 = 50 이 나옵니다!
해결책 (단일행 함수)
  • 연산 전에 반드시 NULL을 치환해야 합니다.
  • NVL(컬럼, 0): NULL이면 0 반환 (오라클)
  • ISNULL(컬럼, 0): SQL Server
  • COALESCE(e1, e2...): NULL이 아닌 첫 번째 값 반환 (표준)

SQL 활용 (고급 쿼리 기법)

조인(JOIN), 서브쿼리, 윈도우 순위 함수 등 오답률이 가장 높은 심화 영역입니다.
진정한 쿼리 마스터로 거듭나는 구간입니다.

2과목 · SQL 활용
조인 (JOIN)의 집합적 이해
-- 부서 테이블: (D1:영업, D2:인사, D3:재무) -- 사원 테이블: (김:D1, 이:D1) SELECT * FROM 부서 LEFT OUTER JOIN 사원 ON 부서.부서코드 = 사원.부서코드;

INNER JOIN

양쪽 매칭 데이터만 (교집합)
결과: 영업(김), 영업(이)

LEFT OUTER JOIN

왼쪽(부서) 데이터 무조건 보존 (왼쪽 100%)
결과: 영업(김), 영업(이), 인사(NULL), 재무(NULL)

FULL OUTER JOIN

매칭 안 되는 양쪽 모두 살림 (합집합)

CROSS JOIN

조건 없이 M × N 곱하기 (카티션 곱)

실무 적용 팁
  • 초보자들은 OUTER JOIN을 두려워하지만, 실무에선 가장 중요합니다.
  • "고객이 한 번도 주문하지 않았더라도, 전체 고객 명단을 조회해야 할 때" LEFT OUTER JOIN을 씁니다. 빈 자리는 NULL로 채워집니다.
2과목 · SQL 활용
서브쿼리와 집합 연산자
위치별 서브쿼리 명칭
SELECT 절스칼라 서브쿼리반드시 단일 행, 단일 열 반환
FROM 절인라인 뷰실행 시 동적 생성되는 가상 테이블
WHERE 절중첩 서브쿼리다중 행 비교(IN, EXISTS) 등에 사용
집합 연산자 (결과 합치기)
UNION합집합 (중복 제거)정렬 O (느림)
UNION ALL합집합 (중복 유지)정렬 X (빠름)
INTERSECT교집합정렬 O
MINUS차집합 (A - B)정렬 O
성능 튜닝 핵심
  • 메인 쿼리는 서브쿼리의 컬럼을 쓸 수 없습니다! (인라인 뷰 제외)
  • UNION ALL을 제외한 모든 집합 연산자는 내부적으로 정렬(SORT) 작업을 동반하여 무겁습니다.
  • 중복이 상관없다면 무조건 UNION ALL을 쓰세요!
2과목 · SQL 활용
윈도우 순위 함수 비교 🏆
윈도우 함수는 `GROUP BY`와 달리 행 수가 줄어들지 않고 원본 데이터를 유지하면서 순위를 매깁니다.
예시 점수: 100, 90, 90, 80점 일 때
함수명출력 순위특징 (동점자 처리 방식)
RANK() 1, 2, 2, 4 동점자는 같은 순위로 묶고, 그만큼 다음 순위를 건너뜁니다. (일반적 방식)
DENSE_RANK() 1, 2, 2, 3 동점자를 같은 순위로 묶되, 순위를 건너뛰지 않고 빽빽하게(Dense) 채웁니다.
ROW_NUMBER() 1, 2, 3, 4 동점자 여부와 전혀 상관없이 무조건 고유한 일련번호를 매깁니다.
무조건 출제 보장
  • SQLD 윈도우 함수 문제의 80%는 이 3가지 순위 함수의 차이점을 묻습니다.
  • OVER (PARTITION BY 부서 ORDER BY 급여 DESC) 구문 형태를 통째로 외워두세요. (부서별 급여 순위)

제 2과목. SQL 기본 및 활용

관리 구문 & 성능 튜닝 기초

단순 쿼리를 넘어 DB의 구조를 변경하는 구문들과,
DB 내비게이션인 '옵티마이저'의 조인 알고리즘을 파헤칩니다.

2과목 · 관리구문 & 튜닝
DELETE vs TRUNCATE vs DROP
명령어언어 분류대상Auto CommitRollback 여부
DELETE DML (조작어) 데이터 (행 단위) X (수동) O (복구 가능)
TRUNCATE DDL (정의어) 데이터 (전체) O (자동) X (복구 불가)
DROP DDL (정의어) 테이블 구조 자체 O (자동) X (복구 불가)
실무 대참사 경고: 오라클에서 DDL 구문은 실행되는 순간 내부적으로 즉시 COMMIT을 날려버립니다. 만약 INSERT 등 DML 작업을 하다가 DDL을 실행하면, 이전 작업도 강제로 커밋되어 버립니다!
차이점 이해하기
  • DELETE는 지우는 기록(Undo 로그)을 일일이 남기기 때문에 느리지만 롤백이 가능합니다.
  • TRUNCATE는 기록 없이 데이터만 통째로 날리므로 압도적으로 빠르지만, 절대 복구할 수 없습니다.

조인 수행 메커니즘 (옵티마이저 원리) 🏆

NL Join (중첩 루프)

이중 For문과 같은 구식 방식.
선행 데이터 1건마다 후행 테이블을 찔러봄.
후행 테이블 인덱스 필수!

Sort Merge Join

두 테이블을 정렬(Sort)한 뒤 쭉 병합.
인덱스가 없거나, 비동등 크기 비교 조인일 때 쓰지만 대용량엔 메모리 부하 큼.

Hash Join

선행 테이블로 메모리에 해시 맵 생성.
랜덤 I/O를 극복하여 대용량 데이터 조인에 가장 압도적인 속도! (= 조인만 가능)

옵티마이저(CBO)는 통계 정보를 바탕으로 위 3가지 알고리즘 중 가장 비용(Cost)이 저렴한 길을 스스로 계산하여 실행 계획을 수립합니다.
실무·시험 핵심 소양
  • 인덱스를 안 타는 경우 (Full Scan 발생):
    1. 인덱스 컬럼 가공 SUBSTR()
    2. 암시적 형변환
    3. 부정형 비교 !=
    4. IS NULL
  • 데이터 웨어하우스(DW) 대용량 집계는 무조건 Hash Join이 주름잡습니다.
