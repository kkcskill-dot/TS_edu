데이터 모델링

모델링 개념·3단계부터 엔터티·속성·관계·식별자까지
— 1과목 1장의 핵심을 한 강좌로. (정규화·성능은 다음 강좌)

모델링 개요
데이터 모델링의 3대 특징

추상화

현실을 일정 형식으로 표현. 공통점을 추출해 표현.

단순화

누구나 이해하도록 약속된 규칙으로 간단히.

명확성(정확성)

의미가 명확하게, 한 가지 뜻으로 해석되게.

모델링 관점 3가지: 데이터(What) · 프로세스(How) · 데이터와 프로세스의 상관(CRUD).
유의사항(자주 출제)
  • 중복 배제 · 비유연성 주의(업무 변화 대응) · 비일관성 방지
  • 모델링 = 정보시스템 구축의 분석/설계 단계 핵심 작업
모델링 개요
모델링 3단계 — 개념 → 논리 → 물리
단계특징산출물
개념적추상화 최고, 업무 중심, 전사적(EA)핵심 엔터티·관계(개략 ERD)
논리적정규화 수행, DBMS 독립, 재사용성 최고속성·식별자·관계 상세 모델
물리적구체화 최고, DBMS 종속, 성능 고려테이블·인덱스·파티션
시험 1순위 함정
  • 정규화는 논리적 단계에서 수행
  • DBMS 종속은 물리적뿐 (개념·논리는 독립)
  • 개념→물리로 갈수록 구체화
  • "논리 모델은 특정 DB에 종속된다?" → NO
모델링 개요
3요소 · 3층 스키마 · 데이터 독립성

데이터 모델 3요소

엔터티(What) · 속성(Attribute) · 관계(Relationship).

3층 스키마

외부(사용자 뷰) · 개념(통합 뷰) · 내부(물리 저장).

데이터 독립성 — 논리적 독립성(외부↔개념: 통합구조 변경에도 뷰 영향 적음) · 물리적 독립성(개념↔내부: 저장구조 변경에도 논리 영향 적음).
암기 포인트
  • 외부=View, 개념=통합, 내부=물리
  • 논리적 독립성: 외부↔개념
  • 물리적 독립성: 개념↔내부
엔터티
엔터티의 6가지 특징
  • 업무에서 필요로 하는 정보일 것
  • 유일한 식별자로 식별 가능
  • 2개 이상의 인스턴스 집합
  • 반드시 속성을 가짐(2개 이상)
  • 업무 프로세스에 의해 이용됨
  • 다른 엔터티와 최소 1개 이상의 관계
단골 오답노트
  • "고립된(관계 없는) 엔터티가 좋다?" → NO
  • "속성 없는 엔터티 존재 가능?" → NO
  • "인스턴스 1개여도 엔터티?" → NO(집합)
  • 예외: 통계성·코드성은 관계 생략 가능
엔터티
엔터티의 분류
유·무형에 따라
유형물리적 형태, 안정적 (사원, 물품)
개념개념적 정보 (조직, 보험상품)
사건업무 수행 중 발생 (주문, 청구, 이벤트)
발생 시점에 따라
기본독립적 생성, 타 엔터티의 부모 (사원·부서·고객)
중심기본에서 발생, 행위의 중심 (계약·주문·접수)
행위2개 이상에서 발생 (주문목록·이력)
구분 팁
  • 기본: 다른 것 없이도 생김(독립)
  • 중심: 기본들이 만나 발생, 데이터량 많음
  • 행위: 2개+ 관계로 생기는 결과/이력
  • 발생시점 순서: 기본 → 중심 → 행위
속성
속성의 분류 & 도메인

기본 속성

업무에서 원래 도출 (회원명, 가입일).

설계 속성

관리 위해 새로 정의 (코드, 일련번호).

파생 속성

다른 속성에서 계산 (합계, 평균) — 최소화.

도메인 = 속성이 가질 수 있는 값의 범위(타입·길이·제약). 예) 점수 0~100, 성별 'M'/'F'.
분해 정도
  • 단일값 · 복합(주소=시/구/동)
  • 다중값은 원자성 위배 → 별도 엔터티로
  • 파생 속성은 정합성 비용 → 꼭 필요할 때만
관계
관계 — 차수(Cardinality) & 선택성

차수

1:1, 1:M, M:N(논리에선 표현, 물리에선 교차 엔터티로 해소).

선택성(Optionality)

필수(●) vs 선택(○) 참여.

관계의 3요소: 관계명(이름) · 관계차수(1:M 등) · 관계선택사양(필수/선택).
관계 페어링
  • 엔터티 인스턴스끼리 연결된 짝(페어링)의 집합이 관계
  • IE 표기: 까마귀발(M), 선 끝 모양으로 필수/선택
  • M:N은 반드시 교차 엔터티로 분해(물리)
관계
M:N 관계 — 교차 엔터티로 해소
학생
M:N
과목
물리 모델에서는 직접 표현 불가 → 수강(교차 엔터티) 추가, 1:M + 1:M으로 분해.
-- 교차 테이블 수강(학번, 과목코드) SELECT st.이름, sb.과목명 FROM 수강 r JOIN 학생 st ON r.학번 = st.학번 JOIN 과목 sb ON r.과목코드 = sb.과목코드;
암기
  • M:N은 반드시 교차 엔터티로
  • 교차 엔터티 PK = 양쪽 PK 조합(+@)
  • 교차 엔터티는 보통 행위 엔터티
관계
식별 관계 vs 비식별 관계
식별 관계비식별 관계
부모 키자식의 주식별자(PK)로자식의 일반 속성(FK)로
표기실선점선
종속강한 종속(부모 없이 불가)약한 종속(독립 존재)
선택 기준
  • 자식이 부모 없이 존재 못 함 → 식별
  • 자식이 독립적으로 존재 → 비식별
  • 식별 관계 남발 → PK가 계속 늘어 복잡(주의)
식별자
식별자의 분류
기준분류
대표성주식별자 / 보조식별자
생성내부(자체) / 외부(다른 엔터티에서, FK)
속성 수단일 / 복합
대체 여부본질(업무 속성) / 인조(대리키)
보조 식별자
  • 유일성은 만족하나 대표성 없어 참조 관계 못 맺음
  • 예: 회원ID가 PK일 때 주민번호는 보조식별자
식별자
본질 식별자 vs 인조 식별자
본질 식별자인조(대리) 식별자
출처업무에서 도출된 속성임의로 부여한 일련번호
예(주문일+고객+상품)주문번호 SEQ
장점의미 명확단순·불변·조인 단순
복합 본질키가 너무 길거나 변할 때 인조키 도입. 단, 본질의 유일성은 UNIQUE로 별도 보장.
도입 시점·함정
  • 본질키 속성 수가 많음(보통 4↑) → 인조키 고려
  • 인조키만 믿고 UNIQUE 누락 → 중복 입력 위험
  • 인조키는 의미가 없어 그 자체로 업무 검증 불가
식별자
주식별자의 4대 특징
  • 유일성 — 인스턴스를 유일하게 구분
  • 최소성 — 유일성 보장하는 최소 속성 집합
  • 불변성 — 한 번 지정되면 값이 바뀌지 않음
  • 존재성 — NULL 불가(반드시 값 존재, NOT NULL)
도출 기준 · 함정
  • 자주 조회·조인되는 속성을 주식별자로
  • "주식별자에 NULL 가능?" → NO(존재성)
  • "주식별자 값이 바뀔 수 있다?" → NO(불변성)
  • 최소성: 불필요한 속성 포함 금지
관계
식별자 상속과 조인

모델의 관계는 부모 PK가 자식으로 상속(FK) 되며, 이 PK–FK가 곧 조인 조건이 됩니다.

식별 관계

부모 PK → 자식 PK 일부 (실선). 조인 키가 PK에 포함.

비식별 관계

부모 PK → 자식 일반 FK (점선). 자식 독립 존재.

-- 관계 = 조인 SELECT * FROM 주문 o JOIN 고객 c ON o.고객번호 = c.고객번호;
핵심
  • PK–FK 조인이 정상 모델의 기본 조인
  • 식별관계 연쇄 → 자식 PK가 점점 길어짐
  • FK 없는 조인(카티션 곱) 주의
트랜잭션
모델이 표현하는 트랜잭션

하나의 트랜잭션으로 함께 발생하는 업무는 모델에서 필수 관계로 묶여야 합니다.

주문 ↔ 주문상세

주문은 상세 1건 이상과 동시 발생 → 필수 관계.

원자성

둘 중 하나만 저장되면 안 됨 → 한 트랜잭션.

관계의 선택성(필수/선택)이 트랜잭션 발생 규칙을 표현한다.
포인트
  • 필수 관계 = 동시 발생 트랜잭션
  • 선택 관계 = 독립적으로 발생 가능
