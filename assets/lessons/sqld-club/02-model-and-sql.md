# 1과목. 데이터 모델링의 이해
## 2장. 데이터 모델과 SQL

> [!TIP]
> **개발자를 위한 가이드**
> 개발을 하다 보면 "조인이 너무 많아서 쿼리가 느려요" 또는 "데이터를 업데이트했는데 한 군데만 반영되고 다른 데는 안 바뀌어서 데이터가 꼬였어요" 라는 말을 자주 듣게 됩니다. 
> 이는 데이터 정규화와 반정규화 사이의 줄다리기가 실패했기 때문입니다. 이 장에서는 성능을 위한 올바른 테이블 설계 기법을 배웁니다.

---

### 1. 정규화 (Normalization) 🏆 (출제 비중 매우 높음)
데이터의 중복을 제거하여 **삽입/삭제/갱신 이상(Anomaly) 현상을 방지**하기 위해 데이터를 분해하는 과정입니다.

*   **제1정규형 (1NF)**: 모든 속성은 반드시 **하나의 원자값(Atomic Value)**만 가져야 합니다. (다중값, 반복 컬럼 제거)
*   **제2정규형 (2NF)**: 주식별자에 종속되지 않는 **부분 함수 종속성**을 제거합니다. (주식별자가 복합키일 때 발생)
*   **제3정규형 (3NF)**: 일반 속성들 간의 종속 관계인 **이행 함수 종속성**을 제거합니다. (A->B, B->C 일 때 A->C가 성립하는 관계 끊기)

> 💡 **정규화의 성능 효과**:
> 데이터가 관심사별로 묶이고 중복이 감소하여 **입력/수정/삭제 성능은 무조건 향상**됩니다. 단, 조회 성능은 조인이 많아질 경우 처리 조건에 따라 저하될 수도 있고 향상될 수도 있습니다.

---

### 2. 반정규화 (Denormalization)
디스크 I/O가 많거나, 조인 경로가 너무 멀어 **조회(SELECT) 성능이 심각하게 저하될 것으로 예상될 때** 데이터 무결성이 깨질 위험을 감수하고서라도 **중복, 통합, 분리**를 수행하는 기법입니다.

#### 반정규화의 기법
1.  **테이블 반정규화**:
    *   **테이블 병합**: 1:1 관계, 1:M 관계 병합, 슈퍼/서브타입 병합
    *   **테이블 분할**: 수직 분할(컬럼 단위), 수평 분할(로우 단위)
    *   **테이블 추가**: 중복 테이블, 통계 테이블, 이력 테이블, 부분 테이블 추가
2.  **컬럼 반정규화** (실무에서 가장 흔함):
    *   **중복 칼럼 추가**: 조인 감소를 위해 다른 테이블의 컬럼을 복사해 옴
    *   **파생 칼럼 추가**: 총합, 평균 등 미리 계산된 값을 컬럼으로 저장
    *   **이력 테이블 칼럼 추가**: 최근 값 여부, 시작/종료일자 등을 추가
3.  **관계 반정규화**: 여러 다리 건너 조인해야 하는 경로를 단축하기 위해 **중복 관계를 추가** (데이터 무결성 영향 없음)

> [!WARNING]
> 반정규화를 무턱대고 적용하기 전에 반드시 **뷰(View), 클러스터링, 인덱스 조정, 애플리케이션 로직 개선**을 먼저 검토해야 합니다! 반정규화는 데이터 무결성을 파괴하므로 최후의 수단이어야 합니다.

---

### 3. 대용량 데이터 발생에 따른 성능 문제
하나의 테이블에 대량의 데이터나 너무 많은 컬럼이 집중되면 디스크 I/O가 급증하여 성능이 저하됩니다.

*   **로우 체이닝 (Row Chaining)**: 로우 길이가 너무 길어 데이터 블록 하나에 다 담지 못하고 **두 개 이상의 블록에 걸쳐 저장**되는 현상.
*   **로우 마이그레이션 (Row Migration)**: 수정된 데이터가 해당 블록의 남은 공간에 다 들어가지 못해 **다른 블록의 빈 공간을 찾아 저장**되는 현상.
*   **해결책**:
    *   컬럼이 너무 많다면 **수직 분할(1:1 관계 테이블로 분할)**을 고려합니다.
    *   데이터 로우가 너무 많다면 **파티셔닝(Partitioning)**을 고려합니다.
        *   `Range Partition`: 날짜, 숫자 범위로 분할 (예: 2023년 데이터, 2024년 데이터)
        *   `List Partition`: 특정 값 기준으로 분할 (예: 서울, 부산, 대전)
        *   `Hash Partition`: 해시 함수를 적용하여 임의 분할 (데이터 균등 분배 목적)

---

### 4. 슈퍼/서브 타입 데이터 모델 변환
논리 모델링 단계에서 쓰이는 '슈퍼/서브 타입' 구조를 물리 DB 테이블로 변환하는 3가지 방식입니다.

1.  **One to One Type (1:1 타입)**: 슈퍼타입과 서브타입을 각각 개별 테이블로 모두 쪼개어 생성. (조인은 많이 발생하지만 확장에 유리)
2.  **Plus Type (슈퍼+서브 타입)**: 각 서브타입마다 슈퍼타입의 공통 컬럼을 합쳐서 각각의 독립된 테이블로 생성.
3.  **Single Type (All in One 타입)**: 하나의 거대한 통합 테이블(통뼈)로 모두 합쳐버림. (조인은 없으나 컬럼 낭비 심함)

---

### 5. 분산 데이터베이스
물리적으로 분산된 데이터베이스를 네트워크를 통해 하나의 논리적 시스템처럼 사용하는 환경입니다.

*   **4대 투명성 (Transparency)** 🏆
    1.  **분할 투명성**: 하나의 논리적 릴레이션이 여러 단편으로 분할되어 저장됨을 감춤.
    2.  **위치 투명성**: 사용자는 데이터가 물리적으로 어느 사이트에 있는지(저장 장소 명시) 알 필요가 없음.
    3.  **지역사상 투명성**: 지역 DBMS와 물리적 DB 사이의 맵핑이 보장됨.
    4.  **장애 투명성**: 특정 노드에 장애가 발생해도 트랜잭션의 원자성은 유지됨.
    5.  *(참고) 병행 투명성: 다수 트랜잭션 동시 수행 시 일관성 유지.*

*   **분산 데이터베이스 적용 기법**: 테이블 위치 분산, 테이블 분할 분산(수평/수직), 테이블 복제 분산(부분/광역), 테이블 요약 분산.
