### 1. 조인 (JOIN)

두 개 이상의 테이블을 이어 붙여 함께 조회하는 기법으로, 관계형 데이터베이스의 핵심이다.

#### 1.1 조인의 종류 (Standard SQL 기준)

| 조인 종류 | 설명 | 교집합 여부 |
| :--- | :--- | :--- |
| **INNER JOIN** | 조인 조건에 맞는 데이터만 뽑는다. 가장 흔한 형태다. | 순수 교집합 |
| **LEFT OUTER JOIN** | 왼쪽 테이블은 전부 살리고, 오른쪽은 조건에 맞는 것만 붙이되 없으면 NULL로 채운다. | 왼쪽 전체 포함 |
| **RIGHT OUTER JOIN** | 오른쪽 테이블을 전부 살린다. | 오른쪽 전체 포함 |
| **FULL OUTER JOIN** | 양쪽에서 매칭되지 않는 데이터까지 모두 살린다. | 합집합 (모두 포함) |
| **CROSS JOIN** | 조건 없이 두 테이블의 모든 행을 곱한다(카티션 곱). A가 3행, B가 4행이면 12행이 된다. | 곱집합 |
| **NATURAL JOIN** | 두 테이블에서 **이름과 타입이 같은 컬럼**을 찾아 자동으로 INNER JOIN 한다. 실무에서는 위험해 잘 쓰지 않는다. | - |

> **주의**: `NATURAL JOIN`은 조건(ON)을 적지 않고 같은 이름의 컬럼을 알아서 찾아 조인한다. 의도치 않게 컬럼명이 겹치면 원치 않는 결과가 나올 수 있다.

#### 1.2 OUTER JOIN 살펴보기

**[A 테이블: 부서]** (D1: 영업, D2: 인사, D3: 재무)
**[B 테이블: 사원]** (김철수: D1, 이영희: D1)

*   `SELECT * FROM 부서 LEFT OUTER JOIN 사원 ON 부서.부서코드 = 사원.부서코드`
    *   **결과**: 영업(김철수, 이영희), 인사(NULL), 재무(NULL).
    *   사원이 한 명도 없는 부서(인사, 재무)까지 빠뜨리지 않고 모두 보고 싶을 때 쓴다.

### 2. 서브쿼리 (Subquery)

하나의 SQL 문장 안에 들어 있는 또 다른 SQL 문장으로, 메인 쿼리를 돕는 보조 역할을 한다.

#### 2.1 위치에 따른 서브쿼리 분류

1.  **스칼라 서브쿼리 (SELECT 절)**: 한 행, 한 컬럼만 돌려주어야 한다. 결과가 여러 개면 에러가 난다.
    *   `SELECT 이름, (SELECT 부서명 FROM 부서 WHERE 부서.부서코드 = 사원.부서코드) FROM 사원;`
2.  **인라인 뷰 (FROM 절)**: 서브쿼리의 결과를 하나의 임시 테이블처럼 쓴다.
    *   `SELECT * FROM (SELECT 이름, 급여 FROM 사원 ORDER BY 급여 DESC) WHERE ROWNUM <= 3;`
3.  **중첩 서브쿼리 (WHERE 절)**: 필터 조건을 동적으로 가져올 때 쓴다.
    *   `SELECT * FROM 사원 WHERE 급여 > (SELECT AVG(급여) FROM 사원);`

#### 2.2 서브쿼리 주의사항
*   서브쿼리는 메인 쿼리의 컬럼을 쓸 수 있지만(연관 서브쿼리), 메인 쿼리는 서브쿼리의 컬럼을 쓸 수 없다. 다만 인라인 뷰는 예외다.
*   여러 건을 돌려주는 서브쿼리는 `IN`, `ANY`, `ALL`, `EXISTS` 같은 다중 행 연산자와 함께 써야 한다. `=`을 썼다가 여러 건이 나오면 에러가 난다.

### 3. 집합 연산자 (Set Operator)

두 개 이상의 SELECT 결과 집합을 하나로 합치는 연산자다.

*   **UNION**: 두 결과의 합집합이다. **중복된 행은 하나로 줄인다.** 이 과정에서 정렬을 하므로 상대적으로 느리다.
*   **UNION ALL**: 두 결과의 합집합이되 **중복도 그대로 모두 출력한다.** 정렬을 하지 않아 빠르다.
*   **INTERSECT**: 두 결과의 교집합이다.
*   **MINUS (EXCEPT)**: 첫 번째 결과에서 두 번째 결과를 뺀 차집합이다.

> 💡 중복 제거가 필요 없거나 두 집합이 겹칠 일이 없다면 `UNION ALL`을 쓰는 편이 성능에 유리하다.

### 4. 윈도우 함수 (Window Function)

행과 행 사이의 관계를 다루기 위한 함수다. `GROUP BY`와 달리 결과 행 수가 줄지 않고 원본 데이터를 그대로 둔 채 집계나 순위를 매길 수 있다.

#### 4.1 순위(Rank) 함수 비교

100점, 90점, 90점, 80점처럼 동점이 있을 때 세 함수가 순위를 다르게 매긴다.

| 함수 | 결과 | 설명 |
| :--- | :--- | :--- |
| **RANK()** | 1, **2, 2, 4** | 동점은 같은 순위로 묶고, 그만큼 다음 순위를 건너뛴다. 가장 흔한 방식이다. |
| **DENSE_RANK()** | 1, **2, 2, 3** | 동점은 같은 순위로 묶되, 다음 순위를 건너뛰지 않고 촘촘하게(Dense) 채운다. |
| **ROW_NUMBER()** | 1, **2, 3, 4** | 동점 여부와 무관하게 고유한 일련번호를 매긴다. |

#### 4.2 그룹 내 비율·행 순서 함수
*   `LAG(컬럼, 1)`: 이전 행의 값을 가져온다. 전월 대비 매출처럼 앞뒤를 비교할 때 쓴다.
*   `LEAD(컬럼, 1)`: 다음 행의 값을 가져온다.
*   `PERCENT_RANK()`: 0~1 사이의 백분율 순위다. 1등이 0, 꼴찌가 1이 된다.
*   `CUME_DIST()`: 현재 행보다 작거나 같은 건수의 누적 백분율이다.

### 5. 계층형 질의 (Hierarchical Query)

조직도나 게시판 답글처럼 트리(Tree) 형태의 계층 구조를 훑을 때 오라클 등에서 쓴다.

*   `START WITH`: 트리의 시작점(루트 노드)을 지정한다. (예: `WHERE 최상위관리자 IS NULL`)
*   `CONNECT BY`: 부모 노드와 자식 노드의 관계를 지정한다.
    *   **순방향 전개**: 부모 → 자식 방향이다. `PRIOR 자식 = 부모` (자식의 값이 이전 행의 부모와 같으면 아래로 내려간다.)
    *   **역방향 전개**: 자식 → 부모 방향이다. `PRIOR 부모 = 자식`
*   `LEVEL`: 계층형 질의에서만 쓰는 가상 컬럼으로, 루트가 1이고 아래로 갈수록 1씩 늘어난다.
