# 2과목. SQL 기본 및 활용
## 2장. SQL 활용 및 최적화 원리

> [!TIP]
> **개발자를 위한 가이드**
> 백엔드 개발자라면 서브쿼리나 조인까지는 익숙하겠지만, **윈도우 함수(Window Function)**나 **계층형 질의**를 다룰 수 있다면 복잡한 통계 로직을 단 한 줄의 SQL로 해결할 수 있습니다. 또한, 이 장의 후반부에 있는 **옵티마이저와 인덱스 원리**는 쿼리 튜닝을 위한 필수 지식입니다.

---

### 1. 표준 조인 (STANDARD JOIN)
ANSI/ISO 표준 방식의 다양한 조인 기능입니다.

*   **INNER JOIN**: 조인 조건에 일치하는 데이터만 반환합니다. (ON 조건절이나 USING 조건절 사용)
*   **NATURAL JOIN**: 두 테이블 간 동일한 이름을 갖는 모든 컬럼에 대해 등가(EQUI) 조인을 수행합니다. (조인 컬럼에 ALIAS 접두사 사용 불가)
*   **OUTER JOIN**: 조인 조건에 일치하지 않는 행도 강제로 출력합니다.
    *   `LEFT OUTER JOIN`: 좌측 테이블 기준
    *   `RIGHT OUTER JOIN`: 우측 테이블 기준
    *   `FULL OUTER JOIN`: 양쪽 모두 읽어옴 (합집합)
*   **CROSS JOIN**: 조건이 없을 때 발생할 수 있는 모든 데이터의 조합 (M * N 건)을 출력합니다. (Cartesian Product)

---

### 2. 집합 연산자 (Set Operator)
조인을 사용하지 않고 2개 이상의 질의 결과를 위아래로 결합하는 방법입니다.

*   **UNION**: 두 쿼리 결과의 합집합. 중복된 행을 제거하기 위해 내부적으로 **정렬(SORT)** 작업을 수행합니다.
*   **UNION ALL 🏆**: 두 쿼리 결과의 합집합. 중복을 제거하지 않아 정렬이 발생하지 않으므로 **성능(속도)이 가장 뛰어납니다.**
*   **INTERSECT**: 두 쿼리 결과의 교집합.
*   **EXCEPT (Oracle은 MINUS)**: 첫 번째 쿼리 결과에서 두 번째 쿼리 결과를 뺀 차집합.

---

### 3. 계층형 질의 (Hierarchical Query)
동일 테이블 내에 계층적으로 상/하위 데이터가 포함된 경우(예: 사원과 매니저 조직도) 이를 탐색하기 위한 쿼리입니다.

*   `START WITH`: 계층 전개의 시작점(루트 노드)을 지정합니다.
*   `CONNECT BY PRIOR`: 자식 데이터를 어떻게 전개해 나갈지 부모-자식 조인 조건을 지정합니다.
    *   `PRIOR 자식 = 부모`: 역방향 전개 (자식에서 부모로)
    *   `PRIOR 부모 = 자식`: 순방향 전개 (부모에서 자식으로)
*   `ORDER SIBLINGS BY`: 형제 노드들 사이에서의 정렬을 수행합니다.

---

### 4. 서브쿼리 (Subquery)
하나의 SQL문 안에 포함된 또 다른 SQL문입니다.

1.  **스칼라 서브쿼리 (SELECT 절)**: 반드시 단 1개의 행과 1개의 컬럼만을 반환해야 합니다.
2.  **인라인 뷰 (FROM 절)**: 메모리에 동적으로 생성되는 임시 뷰입니다.
3.  **중첩 서브쿼리 (WHERE 절)**:
    *   *다중행 비교 연산자*: `IN`, `ALL` (모두 만족), `ANY` (하나라도 만족), `EXISTS` (결과 존재 여부만 확인)

---

### 5. 그룹 함수 (ROLLUP, CUBE, GROUPING SETS)
*   **ROLLUP**: 기술된 컬럼의 순서에 따라 단계별로 소계(Subtotal)를 자동 계산합니다. (순서가 바뀌면 결과도 바뀜)
*   **CUBE**: 결합 가능한 모든 컬럼의 다차원 소계를 생성합니다. (가장 시스템 부하가 큼)
*   **GROUPING SETS**: 원하는 특정 항목에 대한 소계만 개별적으로 지정하여 계산합니다.

---

### 6. 윈도우 함수 (Window Function)
행 간의 관계를 정의하거나 순위, 누적합 등을 구할 때 사용합니다. `GROUP BY`와 달리 결과 건수가 줄어들지 않습니다.

*   **순위 함수** 🏆
    *   `RANK()`: 중복 순위를 포함합니다. (1등, 1등, 3등, 4등...)
    *   `DENSE_RANK()`: 중복 순위를 무시하고 빈틈없이 채웁니다. (1등, 1등, 2등, 3등...)
    *   `ROW_NUMBER()`: 중복 값에도 고유한 일련번호(순위)를 부여합니다. (1등, 2등, 3등, 4등...)
*   **행 순서 함수**: `FIRST_VALUE`(첫 값), `LAST_VALUE`(끝 값), `LAG`(이전 값), `LEAD`(이후 값)
*   **비율 함수**: `RATIO_TO_REPORT`, `PERCENT_RANK`, `CUME_DIST`, `NTILE`

---

### 7. SQL 최적화 기본 원리 (튜닝의 기초) 🚀

#### ① 옵티마이저 (Optimizer)
사용자가 작성한 SQL문을 가장 적은 비용으로 실행할 수 있는 **최적의 실행 계획(Execution Plan)**을 도출해 내는 데이터베이스의 핵심 두뇌입니다.
*   **규칙기반 옵티마이저 (RBO)**: 미리 정해진 규칙(우선순위)에 따라 실행 계획을 생성합니다. (예: 인덱스 스캔이 전체 스캔보다 항상 우선)
*   **비용기반 옵티마이저 (CBO)**: 통계 정보를 바탕으로 여러 대안 계획의 비용(Cost)을 예측하여 가장 비용이 적은 계획을 선택합니다. (현재 대부분의 DBMS가 채택)

#### ② 인덱스 (Index)
검색 속도를 향상시키기 위한 '찾아보기' 기능입니다. 
*   **B-트리 인덱스**: 가장 널리 쓰이는 트리 구조 인덱스입니다.
*   **클러스터형 인덱스**: 테이블의 실제 데이터(리프 노드) 자체가 인덱스 키 순서대로 물리적 정렬이 되어 저장됩니다. (테이블당 1개만 가능)
*   **주의점**: 인덱스를 타면 무조건 빠른 것이 아닙니다. 대량의 데이터를 스캔할 때는 테이블을 통째로 읽는 **전체 테이블 스캔(Full Table Scan)**이 한 건씩 디스크를 찾는 **인덱스 스캔(Index Scan)**보다 유리할 수 있습니다.

#### ③ 조인 수행 원리
1.  **Nested Loop Join (NL 조인)**: 이중 FOR문(반복문)처럼 작동합니다. 선행(Driving) 테이블의 조건을 만족하는 행을 하나씩 읽어 후행 테이블의 인덱스를 찾아 조인합니다. (랜덤 액세스 위주)
2.  **Sort Merge Join**: 두 테이블을 각각 정렬한 후 조인합니다. 넓은 범위의 데이터 처리에 사용되며 조인 컬럼에 인덱스가 없어도 가능합니다.
3.  **Hash Join**: 선행 테이블로 해시 테이블을 만들어 메모리에 올린 뒤 후행 테이블과 조인합니다. **동등(=) 조인에서만 사용 가능**하며, 대량 데이터 처리에 가장 우수한 성능을 보입니다.
