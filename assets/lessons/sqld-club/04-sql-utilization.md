### 1. 조인 (JOIN) 🏆 (시험 무조건 출제)

두 개 이상의 테이블을 연결하여 데이터를 조회하는 기법입니다. 관계형 데이터베이스의 꽃이라 불립니다.

#### 1.1 조인의 종류 (Standard SQL 기준)

| 조인 종류 | 설명 | 교집합 여부 |
| :--- | :--- | :--- |
| **INNER JOIN** | 조인 조건에 일치하는 데이터만 추출합니다. (가장 흔함) | 순수 교집합 |
| **LEFT OUTER JOIN** | 왼쪽 테이블의 모든 데이터는 무조건 살리고, 오른쪽 테이블은 조건이 맞는 것만 붙이며 없으면 NULL로 채웁니다. | 왼쪽 전체 포함 |
| **RIGHT OUTER JOIN** | 오른쪽 테이블의 모든 데이터는 무조건 살립니다. | 오른쪽 전체 포함 |
| **FULL OUTER JOIN** | 왼쪽, 오른쪽 상관없이 매칭 안 되는 데이터도 모두 살립니다. | 합집합 (모두 포함) |
| **CROSS JOIN** | 조건 없이 두 테이블의 모든 행을 카티션 곱(Cartesian Product) 합니다. A가 3행, B가 4행이면 12행이 나옵니다. | 곱집합 |
| **NATURAL JOIN** | 두 테이블에서 **이름과 데이터 타입이 동일한 컬럼**을 찾아 자동으로 INNER JOIN 합니다. (실무에선 위험해서 잘 안 씀) | - |

> 🚨 **주의점**: `NATURAL JOIN`은 조건(ON)을 명시하지 않습니다. 알아서 같은 이름의 컬럼을 찾아 조인합니다. 만약 의도치 않게 컬럼명이 겹치면 원치 않는 결과가 나옵니다.

#### 1.2 OUTER JOIN 시각화

**[A 테이블: 부서]** (D1:영업, D2:인사, D3:재무)
**[B 테이블: 사원]** (김철수:D1, 이영희:D1)

*   `SELECT * FROM 부서 LEFT OUTER JOIN 사원 ON 부서.부서코드 = 사원.부서코드`
    *   **결과**: 영업(김철수, 이영희), 인사(NULL), 재무(NULL).
    *   사원이 한 명도 없는 부서(인사, 재무)도 누락시키지 않고 전부 보고 싶을 때 사용합니다!

### 2. 서브쿼리 (Subquery)

하나의 SQL 문장 안에 포함된 또 다른 SQL 문장입니다. 메인 쿼리를 위해 보조적인 역할을 합니다.

#### 2.1 위치에 따른 서브쿼리 분류

1.  **스칼라 서브쿼리 (SELECT 절)**: 단일 행, 단일 컬럼만 반환해야 합니다. 결과가 여러 개 나오면 에러 발생!
    *   `SELECT 이름, (SELECT 부서명 FROM 부서 WHERE 부서.부서코드 = 사원.부서코드) FROM 사원;`
2.  **인라인 뷰 (FROM 절)**: 서브쿼리의 결과를 마치 하나의 동적인 테이블처럼 사용합니다.
    *   `SELECT * FROM (SELECT 이름, 급여 FROM 사원 ORDER BY 급여 DESC) WHERE ROWNUM <= 3;`
3.  **중첩 서브쿼리 (WHERE 절)**: 필터링을 위한 조건을 동적으로 가져올 때 사용합니다.
    *   `SELECT * FROM 사원 WHERE 급여 > (SELECT AVG(급여) FROM 사원);`

#### 2.2 서브쿼리 주의사항
*   서브쿼리는 메인 쿼리의 컬럼을 사용할 수 있지만(연관 서브쿼리), 메인 쿼리는 서브쿼리의 컬럼을 사용할 수 없습니다. (단, 인라인 뷰 제외)
*   다중 행(여러 건)을 반환하는 서브쿼리는 `IN`, `ANY`, `ALL`, `EXISTS` 등의 다중 행 비교 연산자와 써야 합니다. `=` 썼다가 여러 건이 나오면 에러가 납니다.

### 3. 집합 연산자 (Set Operator)

두 개 이상의 SELECT 문의 결과 집합을 하나로 합치는 연산자입니다.

*   **UNION**: 두 결과 집합의 합집합. **중복된 행은 하나로 제거**합니다. (내부적으로 정렬(Sort) 작업 수행 -> 느림)
*   **UNION ALL**: 두 결과 집합의 합집합. **중복된 행도 그대로 모두 출력**합니다. (정렬 안 함 -> 매우 빠름)
*   **INTERSECT**: 두 결과 집합의 교집합.
*   **MINUS (EXCEPT)**: 첫 번째 결과에서 두 번째 결과를 뺀 차집합.

> 💡 **실무 꿀팁**: 개발할 때 굳이 중복 제거가 필요 없거나, 애초에 두 집합이 겹칠 일이 없다면 무조건 **UNION ALL**을 쓰는 것이 성능에 압도적으로 좋습니다!

### 4. 윈도우 함수 (Window Function) 🏆 (시험 무조건 출제)

행과 행 간의 관계를 쉽게 정의하기 위해 만든 함수입니다. `GROUP BY`와 달리 결과 집합의 행 수가 줄어들지 않고 원본 데이터를 유지하면서 집계/순위를 매길 수 있습니다.

#### 4.1 순위(Rank) 함수 비교 (중요!)

100점, 90점, 90점, 80점 순서일 때, 순위를 매기는 방식이 다릅니다.

| 함수 | 결과 | 설명 |
| :--- | :--- | :--- |
| **RANK()** | 1, **2, 2, 4** | 동점자는 같은 순위로 묶고, 그만큼 다음 순위를 건너뜁니다. (가장 흔한 순위 방식) |
| **DENSE_RANK()** | 1, **2, 2, 3** | 동점자를 같은 순위로 묶되, **다음 순위를 건너뛰지 않고 빽빽하게(Dense)** 채웁니다. |
| **ROW_NUMBER()** | 1, **2, 3, 4** | 동점자 여부와 상관없이 **무조건 고유한 일련번호**를 매깁니다. |

#### 4.2 그룹 내 비율 및 행 순서 함수
*   `LAG(컬럼, 1)`: 이전 행의 값을 가져옵니다. (전월 대비 매출 등 구할 때 최고!)
*   `LEAD(컬럼, 1)`: 다음 행의 값을 가져옵니다.
*   `PERCENT_RANK()`: 0~1 사이의 백분율 순위. 제일 1등이 0, 꼴찌가 1.
*   `CUME_DIST()`: 현재 행보다 작거나 같은 건수의 누적 백분율.

### 5. 계층형 질의 (Hierarchical Query)

오라클 등에서 조직도, 게시판 답글과 같이 트리(Tree) 형태의 계층 구조를 탐색할 때 사용합니다.

*   `START WITH`: 트리의 시작 지점(루트 노드)을 지정합니다. (예: `WHERE 최상위관리자 IS NULL`)
*   `CONNECT BY`: 부모 노드와 자식 노드의 관계를 지정합니다.
    *   **순방향 전개**: 부모 -> 자식 방향. `PRIOR 자식 = 부모` (자식의 값이 이전(PRIOR) 행의 부모와 같다면 내려감)
    *   **역방향 전개**: 자식 -> 부모 방향. `PRIOR 부모 = 자식`
*   `LEVEL`: 계층형 질의에서만 쓰이는 가상 컬럼으로, 루트 노드가 1이고 밑으로 갈수록 1씩 증가합니다.
