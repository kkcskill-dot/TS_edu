# 2과목. SQL 기본 및 활용
## 3장. 관리 구문

> [!TIP]
> **개발자를 위한 가이드**
> 데이터베이스 객체의 생명주기를 다루고, 트랜잭션의 완결성을 보장하며, 권한을 관리하는 명령어들입니다. 특히 데이터 삭제 명령어(`DELETE`, `TRUNCATE`, `DROP`)의 차이를 정확히 아는 것은 실무의 운영 장애 방지를 위해 매우 중요합니다.

---

### 1. DML (Data Manipulation Language)
데이터베이스의 내용물(데이터)을 입력, 수정, 삭제, 조회하는 명령어입니다.

*   `INSERT INTO 테이블명 (컬럼1, 컬럼2) VALUES (값1, 값2);`
*   `UPDATE 테이블명 SET 컬럼명=값 WHERE 조건;`
*   `DELETE FROM 테이블명 WHERE 조건;`
> 💡 **특징**: DML 명령은 절차적이거나 비절차적인 조작을 수행하며, 메모리 버퍼에서만 수행되므로 데이터베이스에 영구 저장하려면 반드시 `COMMIT`을 수행해야 합니다. (SQL Server는 기본이 Auto Commit입니다.)

---

### 2. TCL (Transaction Control Language)
데이터의 무결성을 보장하기 위해 논리적인 작업 단위인 트랜잭션(Transaction)을 제어하는 명령어입니다.

#### 트랜잭션의 4대 특성 (ACID) 🏆
1.  **원자성 (Atomicity)**: 트랜잭션 내의 연산들은 모두 성공적으로 실행되거나 전혀 실행되지 않아야 합니다. (All or Nothing)
2.  **일관성 (Consistency)**: 트랜잭션 전후의 데이터베이스 내용은 무결성 제약조건을 만족해야 합니다.
3.  **고립성 (Isolation)**: 실행 중인 트랜잭션 중간에 다른 트랜잭션이 끼어들어 데이터를 변경할 수 없습니다.
4.  **지속성 (Durability)**: 성공적으로 완료(Commit)된 트랜잭션의 결과는 영구적으로 저장되어야 합니다.

#### TCL 명령어
*   `COMMIT`: 올바르게 반영된 데이터를 데이터베이스에 영구적으로 반영시킵니다. (이전 데이터는 잃어버리며 잠금이 해제됩니다.)
*   `ROLLBACK`: 트랜잭션 시작 이전의 상태로 되돌립니다. (변경 사항 취소)
*   `SAVEPOINT 저장점명`: 롤백할 위치를 지정합니다. (`ROLLBACK TO 저장점명;`을 통해 트랜잭션의 특정 지점까지만 롤백할 수 있습니다.)

---

### 3. DDL (Data Definition Language) & 삭제 명령어 비교 🏆 (면접/시험 단골)
테이블, 인덱스, 뷰 등 데이터베이스 객체(구조)를 생성, 수정, 삭제하는 명령어입니다.
*   `CREATE TABLE`, `ALTER TABLE` (ADD, DROP COLUMN, MODIFY 등), `DROP TABLE`, `RENAME`
*   **주의점**: DDL 명령어는 실행 즉시 **자동으로 COMMIT(Auto Commit) 되므로 롤백이 절대 불가능**합니다.

#### 데이터 삭제 3대장 완벽 비교
| 구분 | 명령어 예시 | 삭제 범위 | 복구(ROLLBACK) | 디스크 용량 (스토리지) | 속도 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DML** | `DELETE FROM EMP;` | 조건에 맞는 **데이터만** | **가능 (O)** | 줄어들지 않음 | 느림 |
| **DDL** | `TRUNCATE TABLE EMP;` | 테이블 안의 **전체 데이터** | **불가능 (X)** | 초기 상태로 비워짐 | 빠름 |
| **DDL** | `DROP TABLE EMP;` | **테이블 객체 구조 자체** | **불가능 (X)** | 완전히 삭제됨 | 빠름 |

---

### 4. DCL (Data Control Language)
데이터베이스 사용자에게 권한을 부여하거나 회수하는 명령어입니다.

*   **권한 부여**: `GRANT 권한 ON 오브젝트 TO 유저명;`
*   **권한 회수**: `REVOKE 권한 ON 오브젝트 FROM 유저명;`
*   **ROLE (역할)**: 다수의 사용자에게 공통된 권한(예: 읽기 권한, 수정 권한)을 일일이 부여하는 대신, 권한들을 하나의 그룹으로 묶어 놓은 객체입니다. 관리가 매우 편리해집니다.

---

### 5. 절차형 SQL (PL/SQL, T-SQL)
SQL의 한계를 극복하기 위해 변수 선언, IF-ELSE 분기, WHILE 반복문 등의 프로그래밍 로직을 사용할 수 있도록 벤더별로 제공하는 절차형 언어입니다. (Oracle: PL/SQL, SQL Server: T-SQL)

#### 프로시저 (Procedure) vs 트리거 (Trigger)
*   **프로시저 (Procedure)**:
    *   사용자가 `EXECUTE` 명령어를 통해 **명시적으로 호출**하여 실행합니다.
    *   내부적으로 `COMMIT`, `ROLLBACK`과 같은 트랜잭션 제어(TCL)가 가능합니다.
*   **트리거 (Trigger)**:
    *   INSERT, UPDATE, DELETE 등 특정 DML 이벤트가 발생할 때 데이터베이스에 의해 **자동으로 실행**됩니다.
    *   내부적으로 `COMMIT`, `ROLLBACK`을 **사용할 수 없습니다.** (호출한 DML과 동일한 트랜잭션에 묶임)
