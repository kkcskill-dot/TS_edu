# 오라클 데이터베이스 파티셔닝(Partitioning) 가이드

테이블 파티셔닝(Partitioning)은 초대용량 테이블이나 인덱스를 더 작고 관리하기 쉬운 물리적 조각(Partition)으로 나누는 기술이다. 논리적으로는 하나의 테이블처럼 동작하지만, 물리적으로는 여러 세그먼트에 분산 저장되어 성능 향상과 관리의 편의성을 동시에 제공한다.

---

## 1. 파티셔닝의 주요 목적 및 기대 효과

1. **성능 향상 (Performance)**
   * **Partition Pruning(파티션 프루닝)**: 쿼리 실행 시 조건절에 부합하지 않는 파티션을 스캔 대상에서 원천적으로 제외하여 I/O 비용을 획기적으로 절감한다.
   * **Partition-wise Join**: 조인 대상 테이블들이 동일한 기준으로 파티셔닝되어 있을 경우, 파티션 단위로 독립적인 조인을 병렬 수행하여 대용량 조인 성능을 극대화한다.
2. **관리 편의성 증대 (Manageability)**
   * 보관 주기가 지난 오래된 데이터를 `DELETE` 명령어 대신 파티션 `DROP`이나 `TRUNCATE`를 통해 시스템 부하 없이 즉각적으로 제거할 수 있다.
   * 특정 파티션에 장애가 발생하더라도 다른 파티션의 데이터에는 정상적으로 접근 가능하여 가용성이 향상된다.

---

## 2. 파티셔닝 기법의 종류

오라클은 데이터의 특성과 비즈니스 요구사항에 맞춰 다양한 파티셔닝 기법을 제공한다.

### 1) Range Partitioning (범위 파티셔닝)
* **개념**: 지정된 컬럼 값의 범위(Range)를 기준으로 데이터를 분할한다.
* **특징**: 주로 이력성 데이터나 로그성 데이터를 관리할 때 사용되며, 날짜(Date) 컬럼을 기준으로 월별, 분기별, 연별로 분할하는 것이 가장 일반적이다.
* **장점**: 시간 범위 기반의 조회 쿼리에서 탁월한 프루닝 효과를 발휘하며, 오래된 데이터의 아카이빙(Archiving) 및 삭제 작업이 매우 용이하다.

### 2) List Partitioning (목록 파티셔닝)
* **개념**: 특정 컬럼의 명시적인 값(List) 목록을 기준으로 데이터를 분할한다.
* **특징**: 데이터 분포가 이산적이고 그룹화가 명확한 기준 컬럼(예: 지역코드, 부서코드, 영업점 코드)에 주로 사용된다.
* **장점**: 업무 로직과 일치하는 명확한 기준을 바탕으로 데이터를 분리 보관할 수 있어 특정 그룹 단위의 통계 산출 및 관리에 유리하다.

### 3) Hash Partitioning (해시 파티셔닝)
* **개념**: 해시 함수(Hash Function)를 통해 반환된 해시 값을 기준으로 데이터를 분산 저장한다.
* **특징**: 데이터의 분포를 균등하게 나누어 물리적인 디스크 I/O를 분산시키는 데 주 목적이 있다.
* **장점**: 특정 파티션에 데이터가 집중되는 데이터 병목(Hot Block) 현상을 방지할 수 있다. 단, Range 파티셔닝처럼 논리적인 범위 기준의 데이터 삭제나 관리는 불가능하다.

### 4) Composite Partitioning (복합 파티셔닝)
* **개념**: 두 가지 이상의 파티셔닝 기법을 결합하여 데이터를 분할한다.
* **특징**: 주 파티션(Main Partition)을 나눈 뒤, 각 파티션 내부를 서브 파티션(Sub-Partition)으로 한 번 더 쪼개는 방식이다.
* **예시**: `Range-Hash` 복합 파티셔닝의 경우, 날짜 범위(Range)로 데이터를 1차 분할하여 관리 편의성을 얻고, 그 내부에서 식별자 기준 해시(Hash) 분할을 통해 I/O 부하를 분산시키는 두 가지 장점을 모두 취할 수 있다.

## 3. 파티션 인덱스 전략

파티션 테이블에 생성하는 인덱스 또한 관리 기준에 따라 두 가지로 분류된다.

### 1) Local Index (로컬 인덱스)
* **개념**: 테이블 파티션과 1:1로 매핑되도록 인덱스도 동일한 구조로 분할 생성된다.
* **장점**: 파티션 관리에 매우 효율적이다. 특정 테이블 파티션을 추가, 삭제(`DROP`), 잘라내기(`TRUNCATE`) 하더라도 다른 파티션의 인덱스에는 영향을 미치지 않으므로 인덱스 재생성(Rebuild) 작업이 불필요하다. 가용성 측면에서 적극 권장되는 방식이다.

### 2) Global Index (글로벌 인덱스)
* **개념**: 테이블의 파티셔닝 구조와 독립적으로, 전체 테이블 데이터를 대상으로 생성되는 통합 인덱스다.
* **단점**: 테이블의 특정 파티션을 변경하거나 삭제할 경우 글로벌 인덱스 전체가 무효화(Unusable)될 수 있으므로 운영 관리에 주의가 필요하다. 주로 기본키(PK) 무결성 유지가 필요할 때 제한적으로 사용된다.
