# 실무 개발자를 위한 핵심 SQL 튜닝 가이드

본 문서는 실무 개발자가 쿼리 최적화 및 장애 진단 시 필수적으로 인지해야 할 핵심 원리 3가지를 요약하여 제공한다.

---

## 1. 실행 계획(Plan) 판독법: 들여쓰기 원칙

오라클의 실행 계획은 계층형 트리(Tree) 구조로 출력된다. 복잡한 형태의 플랜이라도 다음 두 가지 원칙을 적용하면 실행 순서를 명확하게 파악할 수 있다.

1. **최우선 실행 원칙**: 들여쓰기(Indentation)가 가장 깊은(오른쪽으로 가장 많이 들어간) 노드가 가장 먼저 실행된다.
2. **동일 깊이 선위 실행 원칙**: 들여쓰기 깊이가 동일한 형제 노드가 존재할 경우, 위에서 아래 순서로 실행된다.

> **참고**: 자식 노드의 작업이 완료되면, 그 결과 집합(Row Source)은 바로 상위의 부모 노드에게 전달된다. 부모 노드는 하위 노드들로부터 전달받은 데이터를 기반으로 자신의 연산(예: 조인, 정렬)을 수행한다.

### [판독 연습]
```text
| Id  | Operation                     | Name          |
|   1 |  NESTED LOOPS                 |               |
|   2 |   TABLE ACCESS BY INDEX ROWID | TB_USER       |
|*  3 |    INDEX UNIQUE SCAN          | PK_USER       |
|   4 |   TABLE ACCESS BY INDEX ROWID | TB_ORDER      |
|*  5 |    INDEX RANGE SCAN           | IX_ORDER_DATE |
```
* **실행 순서 해독**:
  1. `Id 3` (가장 깊은 노드) 실행 후 결과를 `Id 2`로 전달한다.
  2. `Id 2` 실행을 완료하여 1차 결과 집합을 구성한다.
  3. `Id 5` (다음으로 깊은 노드) 실행 후 결과를 `Id 4`로 전달한다.
  4. `Id 4` 실행을 완료하여 2차 결과 집합을 구성한다.
  5. 최종적으로 `Id 1` (NESTED LOOPS)에서 두 결과를 조인하여 반환한다.

## 2. 인덱스 기초: 주요 데이터 접근 경로(Access Path)

실무에서 가장 빈번하게 발생하는 3가지 데이터 접근 경로는 다음과 같다.

### 1) TABLE ACCESS FULL (전체 테이블 스캔)
* **특징**: 테이블의 첫 블록부터 마지막 블록까지 모두 순차적으로 읽어 들인다. 다중 블록 읽기(Multi-Block I/O)를 사용하므로 대용량 데이터를 처리할 때 유리하다.
* **발생 조건**: 조건절이 존재하지 않거나, 추출해야 할 데이터가 전체의 10~15% 이상을 차지할 때 옵티마이저가 선택한다.

### 2) INDEX UNIQUE SCAN (인덱스 고유 스캔)
* **특징**: 기본키(PK) 혹은 유니크 인덱스를 통해 정확히 단 1건의 데이터를 검색한다. 가장 효율적이고 빠른 접근 경로이다.
* **발생 조건**: 유니크 인덱스를 구성하는 모든 컬럼에 대해 동등(`=`) 조건을 명시했을 때 발생한다.

### 3) INDEX RANGE SCAN (인덱스 범위 스캔)
* **특징**: 인덱스 트리를 수직 탐색한 후, 조건에 부합하는 구간을 수평으로 스캔하는 방식이다.
* **발생 조건**: 범위 조건(`BETWEEN`, `>`, `<`), `LIKE 'ABC%'`, 혹은 비유니크 인덱스에 동등(`=`) 조건을 사용했을 때 발생한다.
* **주의사항**: 인덱스에서 추출한 주소표(ROWID)를 통해 원본 테이블의 블록을 찾아가는 과정은 무작위 접근(Random I/O)을 유발한다. 추출 건수가 많아질수록 시스템 부하가 기하급수적으로 증가하므로 주의가 필요하다.

## 3. 조인 기초: 상황별 조인 수행 전략

오라클 옵티마이저가 두 개 이상의 테이블을 결합할 때 주로 사용하는 두 가지 조인 방식이다.

### 1) NESTED LOOPS (중첩 루프 조인, NL 조인)
* **원리**: 프로그래밍의 중첩 반복문(Nested For Loop)과 동일한 메커니즘을 가진다. 선행 테이블(Driving Table)에서 조건에 부합하는 행을 찾을 때마다 후행 테이블(Driven Table)을 탐색하여 결합한다.
* **장점**: 첫 번째 결과 행을 즉시 반환하므로, 사용자 화면에서 빠르게 결과를 확인해야 하는 온라인 트랜잭션 처리(OLTP) 환경에 적합하다.
* **주의사항**: 후행 테이블의 조인 조건 컬럼에 인덱스가 존재하지 않을 경우, 선행 테이블의 추출 건수만큼 후행 테이블 전체 스캔(Full Scan)이 반복되어 심각한 성능 저하가 발생한다.

### 2) HASH JOIN (해시 조인)
* **원리**: 조인 대상 중 크기가 작은 테이블을 메모리(PGA)에 올려 해시 테이블을 생성한 뒤, 큰 테이블을 전체 스캔하며 메모리 내 해시 테이블과 매칭한다.
* **장점**: 대용량 데이터를 일괄 처리할 때 NL 조인 대비 월등한 처리 속도를 보장한다. 통계 추출 및 배치 프로그램에 주로 사용된다.
* **주의사항**: 동등(`=`) 조인 조건에서만 사용 가능하다. 또한 메모리 영역(PGA)을 대량으로 사용하며, 모든 데이터 처리가 완료된 후에 결과를 반환하므로 최초 응답 속도는 지연될 수 있다.
