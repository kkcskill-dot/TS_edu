# 2장. 인덱스 기본

인덱스는 책의 **색인**과 같다. 정렬된 키로 원하는 행의 위치(ROWID)를 빠르게 찾는다.

## 2.1 인덱스 구조 및 탐색

### B*Tree 인덱스 구조
```
            [루트]
          /   |   \
     [브랜치] [브랜치] [브랜치]
      / | \    ...
  [리프][리프][리프] → (키값 + ROWID), 리프끼리 양방향 링크
```
- **루트→브랜치→리프**로 내려가며(수직적 탐색) 시작 지점을 찾고,
- 리프 블록을 **좌우로 스캔**(수평적 탐색)하며 조건에 맞는 ROWID를 수집한다.

### 수직적 탐색 vs 수평적 탐색
- **수직적 탐색**: 루트에서 리프까지 내려가는 과정(탐색 시작점 찾기).
- **수평적 탐색**: 리프 블록을 따라가며 데이터를 읽는 과정(실제 스캔량 = 성능).

### 결합 인덱스
여러 컬럼으로 만든 인덱스 `(C1, C2, C3)`. **선두 컬럼 순서로 정렬**된다.
> 선두 컬럼(C1)이 조건에 없으면 Range Scan 시작점을 못 잡는다 → 인덱스 컬럼 순서가 핵심(3장).

## 2.2 인덱스 기본 사용법

### 인덱스를 Range Scan 할 수 없는 경우
인덱스 **선두 컬럼을 가공**하면 정렬 순서가 깨져 Range Scan 불가 → 풀스캔/Skip Scan.
```sql
-- ❌ 인덱스 못 씀 (컬럼 가공)
WHERE SUBSTR(name, 1, 3) = '홍길동'
WHERE sal * 12 > 50000
WHERE NVL(deptno, 0) = 10
-- ✅ 가공을 우변으로
WHERE name LIKE '홍길동%'
WHERE sal > 50000 / 12
```

### 자동(묵시적) 형변환
타입이 다르면 옵티마이저가 **컬럼 쪽**에 형변환을 걸어 인덱스를 무력화한다.
```sql
-- num_col NUMBER 인데 문자 비교 → TO_NUMBER(num_col) 발생, 인덱스 불가
WHERE num_col = '12345'
-- ✅ 타입 일치
WHERE num_col = 12345
```

### 인덱스를 이용한 소트 생략
인덱스는 이미 정렬돼 있으므로, `ORDER BY`가 인덱스 순서와 같으면 **소트 연산을 생략**한다(5장).

### ORDER BY / SELECT-List 컬럼 가공
`ORDER BY`나 `SELECT` 절에서 인덱스 컬럼을 가공해도 소트 생략·커버링 효과를 잃을 수 있다.

## 2.3 인덱스 확장 기능 (스캔 방식)
| 스캔 | 설명 | 쓰임 |
|---|---|---|
| **Index Range Scan** | 선두 컬럼 조건으로 범위 스캔 | 가장 일반적 |
| **Index Unique Scan** | 유니크 인덱스 단건 | PK 등치 조회 |
| **Index Full Scan** | 인덱스 전체를 순서대로 | 소트 대체·커버링 |
| **Index Fast Full Scan** | 인덱스를 Multiblock으로(순서 무시) | 카운트·집계 |
| **Index Skip Scan** | 선두 컬럼 분포 적을 때 건너뛰며 | 선두 누락 보완 |
| **Index Range Scan Descending** | 역순 범위 스캔 | 최신·최대값 |

> ✅ **2장 핵심**: 인덱스는 정렬된 구조라 **선두 컬럼을 가공하지 않아야** Range Scan이 가능하다. 형변환·컬럼가공이 인덱스 무력화의 양대 원인. (실습: 인덱스 시뮬레이터 ♻️ · 플랜 진단 기초 ♻️)
