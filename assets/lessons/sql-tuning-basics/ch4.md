# 4장. 조인 튜닝

조인 방식 3가지(NL·소트머지·해시)의 원리와 선택 기준을 이해한다.

## 4.1 NL(Nested Loops) 조인
```
for 선행(구동) 테이블의 각 행:        -- Outer
    for 후행 테이블에서 조인되는 행:   -- Inner (보통 인덱스)
        결과 출력
```
- **메커니즘**: 구동 테이블 1건마다 후행을 반복 탐색.
- **튜닝 포인트**: ① **작은 결과집합을 구동**으로(LEADING) ② 후행 **조인 컬럼에 인덱스** ③ 후행 랜덤 액세스(CF) 관리.
- **유리**: 소량 데이터·OLTP·부분범위 처리. **불리**: 대량(반복 폭증).
```sql
SELECT /*+ LEADING(d e) USE_NL(e) */ ...   -- 순서·방식 제어
```

## 4.2 소트 머지 조인
- **메커니즘**: 양쪽을 **각각 정렬**한 뒤 머지하며 조인.
- **SGA vs PGA**: 정렬은 세션 전용 **PGA(Sort Area)** 에서 수행.
- **유리**: 조인 컬럼에 인덱스가 없고 대량이며, 정렬이 이미 돼 있거나 부등호(`>`,`<`) 조인일 때. 실무에선 해시 조인에 자리를 많이 내줌.

## 4.3 해시 조인
```
1) 작은 쪽(Build Input)으로 메모리에 해시 테이블 생성
2) 큰 쪽(Probe)을 읽으며 해시로 매칭
```
- **빠른 이유**: 양쪽을 **한 번씩만** 읽고, 인덱스·정렬 불필요.
- **대용량 Build Input**: 메모리 부족 시 디스크로 분할(One/Multi-Pass) → TEMP 사용.
- **유리**: 대량 × 대량, 등치(`=`) 조인. **주의**: 작은 쪽이 Build가 되도록.
```sql
SELECT /*+ USE_HASH(b) */ ...
```

### 조인 메소드 선택 기준 (요약)
| 상황 | 선택 |
|---|---|
| 소량, 후행 인덱스 有 | **NL** |
| 대량 × 대량, 등치 | **Hash** |
| 인덱스 없는 대량·부등호 조인 | **Sort Merge** |

## 4.4 서브쿼리 조인
- **서브쿼리 변환(Unnesting)**: 옵티마이저가 서브쿼리를 조인으로 풀어 더 나은 계획을 찾는다.
- **뷰 머지**: 인라인 뷰를 바깥 쿼리와 합쳐 최적화. 단, **분석함수·ROWNUM** 등이 있으면 머지 억제(VIEW 노드 등장 → 대량 처리 위험).
- **스칼라 서브쿼리**: SELECT 절 서브쿼리는 캐싱되지만 입력값 종류가 많으면 반복 실행 부하.

```sql
-- 상관 서브쿼리 → 조인/분석함수로 풀면 1회 스캔
SELECT e.*, (SELECT d.dname FROM dept d WHERE d.deptno=e.deptno) FROM emp e;
```

> ✅ **4장 핵심**: NL=소량·인덱스, Hash=대량·등치, Sort Merge=인덱스 없는 대량. 구동 테이블·조인 순서가 NL 성능을 좌우. (실습: 조인 비교 실험실 ♻️ · 조인 문법 ♻️ · 뷰 머지 ♻️)
