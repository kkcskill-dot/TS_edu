# 1장. 데이터 모델링 이론

## 1.1 데이터 모델링이란

**데이터 모델링**은 현실 세계의 업무(요건)를 **데이터 구조로 추상화**해 표현하는 작업입니다. 목적은 단순히 "테이블을 그리는 것"이 아니라, 업무 규칙을 빠짐없이·중복 없이 담아내는 **설계도**를 만드는 데 있습니다.

**좋은 모델의 조건**
- **완전성**: 업무에 필요한 데이터를 빠짐없이 표현
- **중복 배제**: 같은 사실을 한 곳에만 저장(One Fact, One Place)
- **업무 규칙 반영**: 제약·관계로 규칙을 강제
- **유연성**: 변화에 견디는 구조

**추상화 3수준** — 모델링은 한 번에 완성되지 않고 단계적으로 정밀해집니다.

| 수준 | 관점 | 산출물 | DBMS 종속 |
|---|---|---|---|
| **개념 모델** | 무엇을(핵심 주제) | 핵심 엔티티·관계 | 독립 |
| **논리 모델** | 어떻게 구조화(상세) | 엔티티·속성·관계, 정규화 | 독립 |
| **물리 모델** | 어떻게 저장(구현) | 테이블·컬럼·인덱스·파티션 | 종속 |

> 이 과정은 **개념 → 논리 → 물리** 순서로 진행합니다. 물리의 **성능·운영 심화**(테이블스페이스·통계·파티션 운영)는 다음 과정 *고성능 DB 설계*에서 다룹니다.

## 1.2 ER 모델 구성 요소

**ERD(Entity-Relationship Diagram)** 는 데이터 모델을 시각화하는 표준 표기입니다.

- **엔티티(Entity)**: 업무에서 관리할 대상(명사). 예) `고객`, `주문`, `상품`
- **속성(Attribute)**: 엔티티가 갖는 성질. 예) 고객의 `이름`, `가입일`
- **식별자(Identifier)**: 엔티티의 각 인스턴스를 유일하게 구분하는 속성(주식별자 = PK 후보)
- **관계(Relationship)**: 엔티티 간의 업무적 연관. 예) 고객이 주문을 *한다*

**카디널리티(Cardinality)** — 관계에 참여하는 수
- `1 : 1` — 한 명의 사원과 한 개의 사번
- `1 : N` — 한 고객이 여러 주문 (가장 흔함)
- `M : N` — 여러 학생이 여러 과목 (→ 논리에서 교차 엔티티로 해소)

**선택성(Optionality)** — 참여가 필수(◼)인지 선택(○)인지. 예) "주문에는 반드시 고객이 있다"(필수), "고객은 주문이 없을 수도 있다"(선택)

표기법은 **IE(까마귀발)** 와 **바커(Barker)** 가 대표적이며, 까마귀발 표기에서 선의 끝 모양으로 1/N과 필수/선택을 나타냅니다.

## 1.3 관계형 데이터 모델 이론

물리 구현의 토대가 되는 **관계형 모델(Relational Model)** 의 핵심 용어:

| 모델링 용어 | 관계형 용어 | 물리(테이블) |
|---|---|---|
| 엔티티 | 릴레이션(Relation) | 테이블 |
| 인스턴스 | 튜플(Tuple) | 행(Row) |
| 속성 | 애트리뷰트 | 컬럼 |
| 속성값 범위 | 도메인(Domain) | 데이터 타입·CHECK |

**키(Key)**
- **후보키(Candidate Key)**: 행을 유일 식별할 수 있는 최소 속성 집합
- **기본키(Primary Key)**: 후보키 중 대표로 선정(NOT NULL·유일)
- **대리키(Surrogate Key)**: 업무 의미 없는 인조 식별자(시퀀스 등)
- **외래키(Foreign Key)**: 다른 릴레이션의 키를 참조 → 관계를 구현

**무결성 규칙(Integrity)**
- **개체 무결성(Entity Integrity)**: 기본키는 NULL일 수 없고 유일하다
- **참조 무결성(Referential Integrity)**: 외래키 값은 참조 대상에 반드시 존재하거나 NULL이어야 한다

```sql
-- 참조 무결성: 주문의 cust_id는 반드시 존재하는 고객이어야 한다
CREATE TABLE orders (
  order_id  NUMBER       PRIMARY KEY,
  cust_id   NUMBER       NOT NULL REFERENCES customer(cust_id),
  order_dt  DATE         NOT NULL
);
```

이 이론적 토대(엔티티·관계·키·무결성) 위에서, 다음 장부터 **개념 → 논리 → 물리** 모델을 단계적으로 만들어 갑니다.
