# 3장. 논리 모델링

## 3.1 논리 모델링이란

**논리 모델링**은 개념 모델을 **상세화**해, DBMS에 독립적인 완성된 데이터 구조를 만드는 단계입니다. 산출물은 **엔티티·속성·관계·식별자 + 정규화된 구조**입니다. (특정 DB의 타입·인덱스는 아직 정하지 않습니다 — 그것은 물리 단계.)

## 3.2 엔티티 정의 및 상세화

- **도출·검증**: 개념 엔티티가 진짜 엔티티인지 확인(독립적 식별자·다수 인스턴스·관리 필요성)
- **슈퍼/서브타입(Supertype/Subtype)**: 공통 속성은 슈퍼타입에, 고유 속성은 서브타입에
  - 예) `회원`(슈퍼) → `개인회원`/`법인회원`(서브). 공통(아이디·가입일)은 위, 고유(생년월일/사업자번호)는 아래
- **통합/분리 판단**: 너무 잘게 쪼개면 조인 폭증, 너무 합치면 NULL·중복 → 4장·5장에서 트레이드오프

## 3.3 관계 도출 및 정의

**식별 관계 vs 비식별 관계**
- **식별 관계**: 부모의 키가 자식의 **기본키 일부**가 됨(자식이 부모 없이 존재 불가). 실선.
  - 예) `주문` ─ `주문상품`(주문번호가 PK의 일부)
- **비식별 관계**: 부모의 키가 자식의 **일반 외래키**(자식이 독립 식별자 보유). 점선.
  - 예) `부서` ─ `사원`(사원은 자체 사번 보유)

**M:N 관계 해소** — 관계형 모델은 M:N을 직접 표현할 수 없습니다. **교차(연관) 엔티티**로 분해합니다.

```text
[주문] M : N [상품]
  ↓ 교차 엔티티로 분해
[주문] 1 : N [주문상품] N : 1 [상품]
   주문상품(PK: 주문번호+상품번호, 속성: 수량·단가)
```

**자기참조·순환관계** — 같은 엔티티끼리 관계(예: 사원-관리자, 카테고리 계층). 외래키가 자기 테이블을 참조합니다. 순환은 데이터 입력 순서·삭제에 주의(5장 케이스 참고).

## 3.4 속성 도출 및 정의

- **원자성(Atomicity)**: 한 속성에 한 값(주소를 시/구/동으로 나눌지 결정). "전화번호1,2,3" 같은 반복 속성은 분리
- **파생/유도 속성**: 다른 값에서 계산되는 값(나이=오늘-생년월일, 합계). **저장 vs 계산** 트레이드오프(저장하면 정합성 관리 비용)
- **도메인 정의**: 속성이 가질 수 있는 값의 범위·타입·규칙(예: 상태 = {접수, 결제, 배송, 완료})
- **NULL 의미**: "값이 없음"인지 "모름"인지 "해당없음"인지 구분해 설계

## 3.5 데이터 표준화

여러 사람이 모델링하면 같은 개념이 다른 이름으로 흩어집니다(`cust_nm` vs `customer_name` vs `고객성명`). **표준화**로 일관성을 확보합니다.

- **표준 단어**: 업무 용어 → 약어 사전(고객=CUST, 주문=ORD, 일자=DT)
- **표준 도메인**: 타입·길이 규칙(금액=NUMBER(15), 일자=DATE, 여부=CHAR(1) Y/N)
- **표준 용어·네이밍**: `[수식어]+표준단어` 조합 규칙(주문일자 = ORD_DT)
- **표준 준수 검증**: 모델의 컬럼명이 사전을 따르는지 점검

> 표준화는 지루하지만, **조인·통합·유지보수 비용을 가장 크게 줄이는** 투자입니다.

## 3.6 정규화 (논리 모델링의 핵심)

**정규화**는 **함수 종속(Functional Dependency)** 에 따라 테이블을 분해해 **중복과 이상현상(Anomaly)** 을 제거하는 과정입니다.

**이상현상** — 중복이 부른 부작용
- **삽입 이상**: 주문이 없으면 상품 정보를 못 넣음
- **갱신 이상**: 상품명이 여러 행에 중복 → 일부만 바뀌어 불일치
- **삭제 이상**: 마지막 주문을 지우면 상품 정보까지 사라짐

**정규형 단계**

| 정규형 | 제거 대상 | 한 줄 규칙 |
|---|---|---|
| **1NF** | 반복 그룹·다중값 | 모든 속성은 원자값 |
| **2NF** | 부분 함수 종속 | 기본키 *전체*에 종속(복합키일 때) |
| **3NF** | 이행 함수 종속 | 키가 아닌 속성 간 종속 제거 |
| **BCNF** | 결정자가 후보키가 아닌 종속 | 모든 결정자는 후보키 |

> 실습 **「정규화 변환기」** 에서 비정규 테이블을 1NF→2NF→3NF로 단계 분해하며 각 단계가 어떤 이상현상을 없애는지 직접 확인하세요.

**반정규화(Denormalization)** — 정규화가 끝이 아닙니다. 조회 성능을 위해 **의도적으로** 중복을 허용하기도 합니다.
- 조회↔갱신 **트레이드오프**: 중복을 두면 조인이 줄지만, 갱신 시 정합성 관리 비용 발생
- 대표 기법: 컬럼 중복(자주 함께 보는 값), 파생/집계 컬럼, 요약 테이블
- **원칙**: 먼저 정규화로 올바른 구조를 만든 뒤, **측정된 병목**에 한해 반정규화

물리적 적용·운영은 4장(물리 모델링)과 다음 과정에서 다룹니다.
