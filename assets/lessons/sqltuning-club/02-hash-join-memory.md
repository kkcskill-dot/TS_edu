# 2회차: 대용량 해시 조인과 메모리 튜닝

> 💡 **학습 목표**
> 실무에서 가장 많이 마주하는 조인 방식인 **해시 조인(Hash Join)**의 내부 메커니즘을 뜯어보고, 메모리(PGA) 크기가 성능에 미치는 엄청난 영향력을 확인합니다.

---

## 1. 해시 조인의 3가지 모드와 비용 차이

해시 조인은 작은 쪽 테이블(Build Input)을 메모리(PGA)에 올려 해시 맵을 만든 뒤, 큰 쪽 테이블(Probe Input)을 스캔하며 해시 맵을 탐색하는 방식입니다. 이때 **PGA 메모리 여유 공간**에 따라 3가지 방식으로 나뉩니다.

### ① In-Memory 해시 조인 (Best)
- Build Input이 PGA 메모리에 한 번에 쏙 들어가는 경우입니다.
- 디스크 I/O가 발생하지 않아 성능이 압도적으로 좋습니다.

### ② 1-Pass 해시 조인 (Warning)
- Build Input이 메모리보다 커서, 맵을 만들다가 메모리가 꽉 차면 남은 데이터를 디스크(Temp 영역)에 잠시 기록합니다.
- 전체 데이터를 디스크에 딱 **한 번** 썼다가 읽어옵니다. 속도가 약간 떨어지지만 버틸 만합니다.

### ③ Multipass 해시 조인 (Critical Danger)
- Build Input이 메모리보다 지나치게 커서, 디스크(Temp)를 썼다 지웠다를 **수없이 반복**하는 상황입니다.
- **장애 사례**: "야간 배치가 아침 9시가 넘도록 안 끝납니다!"
- 이 단계로 넘어가면 디스크 I/O 병목으로 인해 성능이 수십 배 이상 곤두박질칩니다.

---

## 2. PGA_AGGREGATE_TARGET 파라미터의 역할

> [!TIP]
> `PGA_AGGREGATE_TARGET`은 데이터베이스가 세션들에게 할당할 총 PGA 메모리의 목푯값입니다.

- 해시 조인은 이 PGA 메모리를 직접적으로 소모합니다. 
- 메모리가 부족하면 옵티마이저는 강제로 해시 조인 대신 Nested Loops 조인을 선택하거나, 위에서 언급한 Multipass 해시 조인으로 추락하게 만듭니다.
- **DBA의 팁**: 시스템에 여유 메모리가 있다면 세션별 최대 PGA 할당 한도를 늘려주어 대규모 배치의 해시 조인 속도를 비약적으로 향상시킬 수 있습니다.

---

## 3. 조인 최적화와 메모리 통제 전략

대량의 데이터를 정제(ETL)하거나 조인할 때는 **"가장 작은 집합을 메모리에 올리는 것"**이 최우선 전략입니다.

### 실전 메모리 통제 가이드
1. **Build Input 줄이기**: 해시 맵을 만드는 쪽(작은 테이블)에 불필요한 컬럼이 있다면 SELECT 절에서 과감히 제외하세요. 해시 맵의 덩치가 줄어 In-Memory 조인으로 풀릴 확률이 높아집니다.
2. **조인 순서 명시**: 옵티마이저가 통계정보의 오차로 큰 테이블을 Build Input으로 잡는 대참사를 막기 위해 `/*+ LEADING(A B) USE_HASH(B) */` 와 같은 힌트로 조인 순서와 방식을 강제 통제해야 합니다.
3. **Temp 영역 모니터링**: V$SQL_WORKAREA 뷰를 통해 현재 쿼리가 1-Pass인지 Multipass인지 실시간으로 진단하고 튜닝 포인트를 잡습니다.
